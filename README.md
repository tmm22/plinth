# Plinth

Plinth is a native SwiftUI macOS client for the [Slant 3D V2 API](https://slant3dapi.com/documentation/introduction) and, if you choose it as your print service, for [3DAPI](https://www.dapi.digital). Import an STL, OBJ or 3MF model (from the Import panel, drag and drop, or Finder’s **Open With**), preview geometry, upload to your platform, estimate cost, draft an order, and submit for production—with an API Workbench covering every documented Slant operation. With 3DAPI, quote a model, then compose, review and place the order (see [Choosing a print service](#choosing-a-print-service)).

Plinth is an independent app, not made, endorsed or supported by Slant 3D or 3DAPI. It works with their public APIs using your own API keys. Plinth was formerly called Slant Studio (see [Moving from Slant Studio](#moving-from-slant-studio)).

## Run

Requires macOS 14+ and Xcode 16+ / Swift 6. Euclid 0.10.0 (MIT) is pinned for solid geometry operations; its licence ships with the app.

```sh
swift test
./scripts/build-app.sh
open "dist/Plinth.app"
```

You need a Slant 3D account and an API key: create the key in your Slant 3D dashboard at <https://slant3dapi.com>, then paste it into **Plinth › Settings… › Account** (its **Get an API Key** link opens the same site). To print with 3DAPI instead, you need a 3DAPI integrator account and key (see [Printing with 3DAPI](#printing-with-3dapi)).

Or open `Package.swift` in Xcode / `swift run Plinth`. Packaging is ad-hoc signed for the current Mac; public distribution needs Developer ID signing and notarization. The script never removes an earlier `dist/Slant Studio.app` build (your way back to the old app); when one is there it says so after building. Delete it once you no longer need it; until then **Open With** may list the app twice.

## Moving from Slant Studio

Plinth was called Slant Studio. The first time Plinth opens on a Mac that has Slant Studio's data, it brings that data over once:

- **Quit Slant Studio first.** If it is still running and there is something to bring over, Plinth asks you to quit it (**Try Again** once you have, or **Quit Plinth**) and touches nothing until it has.
- **Settings** (default platform, owner ID, order updates, preparation switches, Shopify store address, photo-sharing answers and the rest) are copied. A setting Plinth already has is never overwritten.
- **Library** (models, thumbnails, saved products, order-update history and your saved address) is copied, checked, and only then used, from `~/Library/Application Support/SlantStudio/` to `~/Library/Application Support/Plinth/`. If the copy can't be completed, Plinth works in the Slant Studio folder where it is for that session (so anything you change then is saved there), says so, and tries again the next time it opens; nothing is deleted. Plinth never merges into a library it already has: if Plinth already has its own library, it keeps it, leaves Slant Studio's in its own folder, and says so until you choose **Dismiss**.
- **Keys** (the Slant API key, the Shopify connection, and the Anthropic, Meshy and Tripo keys) move one at a time, the first time Plinth needs each. macOS may ask whether Plinth may use each key saved by Slant Studio: enter your Mac password and choose **Always Allow**. If you deny it, Plinth shows its usual saved-key error, leaves Slant Studio's key as it is, and asks again the next time it needs that key.
- **Order notifications** are off until you allow them again, and **Use Current Location** asks for permission again, because macOS treats Plinth as a new app. When notifications were on in Slant Studio, Plinth says so, with **Turn On Notifications…**, until you turn them on or dismiss it.
- **Don't run both apps at once.** Whenever Slant Studio is open alongside Plinth, Plinth shows a notice asking you to quit it: the two apps don't share their payment and draft safeguards (the lock after a payment or cancellation with an unclear outcome, the warning about unconfirmed drafts, and the question before quitting while Slant is answering), so one app can't stop you paying or creating a draft twice through the other.

Slant Studio's folder, preferences and Keychain items are left where they are, and Plinth doesn't update them afterwards (except on a launch whose copy failed, when Plinth works in Slant Studio's folder), so going back to Slant Studio shows your data as it was when you moved. **Disconnect…** or **Remove…** for a key in Plinth also deletes Slant Studio's copy of that key, so Slant Studio loses it too, and **Remove** for your saved address also deletes Slant Studio's copy of the address (unless Plinth kept a separate library of its own). Once you are happy with Plinth, you can delete the leftovers: the Slant Studio app, the `~/Library/Application Support/SlantStudio/` folder, the Keychain items named `SlantStudio` (in Keychain Access), and its preferences (`defaults delete app.slantstudio.mac` in Terminal).

## Connect and print

The sidebar lists **Models**, **Orders** and **Catalog** (materials, components and stationery). Everything about your Slant account lives in **Settings** (**Plinth › Settings…**, ⌘,), which the account status under the sidebar also opens; the status names the chosen print service (such as “Connected to Slant 3D”, “Slant 3D · Not connected” or “Connected to 3DAPI”). The first section of **Settings › Account**, **Print service**, chooses Slant 3D (the default) or 3DAPI for Models' next steps, Orders and Catalog; this section describes Slant 3D, and [Choosing a print service](#choosing-a-print-service) what changes with 3DAPI. While Slant 3D is the print service and no key is saved, Orders and Catalog (and Models while the library is empty) show **Connect Slant Account…**, which opens Settings. Plinth opens on the sidebar section you used last (a developer section only while developer tools are on).

1. **Settings › Account** — save your API key to the Keychain and test it, choose the default platform, and manage platforms: create, edit, disable and re-enable (by ID), send a test webhook, rotate the webhook secret (type `rotate` to confirm; if Slant doesn't answer clearly or returns no new secret, Plinth stops showing the old one, since Slant may already have changed it, and offers **Reload Platform**; the rotate is never sent again), and load or resend webhook deliveries that failed in the last 30 days (**Recent deliveries**, each listed by its event, with its status, your endpoint's last reply and when it was last tried; **Try Again** shows what your endpoint returned, and isn't offered for delivered or expired ones). Editing a platform sends only the details you changed. A new platform becomes the default only when you have no default yet; otherwise your default stays, because changing it moves uploads and drafts, resets order updates and stops a running import (choose it in Settings when you want it). A platform's **Shop address** is where you sell: your Etsy shop page, your Shopify store or your own website, starting with https://. **Settings › Account › Shopify (optional)** connects your own Shopify store (see [Shopify connection](#shopify-connection)), and **Settings › Account › 3DAPI (optional)** (headed **3DAPI** while it is the print service) holds a 3DAPI integrator key for quotes and, with 3DAPI as the print service, orders (see [Printing with 3DAPI](#printing-with-3dapi)). **Settings › Advanced** shows usage, rate limits and service status, the platform ID (with **Copy**, and a field to use a pasted ID if platforms can’t be listed) and the optional owner ID sent with uploads and drafts. Billing is managed on Slant’s website. Press Return in the key field to save and test it. Changing or removing the key waits until no request is running and nothing (such as a Pay review or an open draft) is open in the main window. Platform errors appear in Settings itself, and a failed Disable keeps the platform’s details open. Payment, cancel and draft-creation safeguards last for the whole session, even if you change the key.

   **Settings › Account › Your address (for samples)** can save your own address on this Mac (opt-in; **Remove…** deletes it). **Use My Address** in the order composer fills it in, asking first if the form already has details or a country you chose (Return keeps them). Customer addresses are still never saved.
2. **Models** — import/drop an STL, OBJ or 3MF for local preview. Uploads send the file in its original format. With no model selected, Models shows a single prompt with **Import Model…** (and **Connect Slant Account…**, which opens Settings, while no API key is saved); the next-action bar appears once a model is selected. Before any account is connected, files dropped on the connect prompt are imported the same way. The optional geometry tools are grouped under **Improve for printing** (STL models), in the order they are usually used: the **Review for printing** card at the top (see [Design tools](#design-tools-optional)), then, all collapsed, **Repair and simplify**, **Size and base**, **Optimise for purpose**, **Auto-improve**, **Reinforce this part**, and **Design improvements** when it can edit the model. Tools that change the model save a separate copy and keep your original. In **Optimise for purpose**, choose the part’s use and stress direction where needed, then **Optimise & Save Copy**. For a long part, **Lay It Flat Along Its Length…** sets the stress direction to its longest side after showing the placement, overhangs and bed contact it would give; nothing is saved until **Set Stress Direction**, and you then make a new copy. It isn't offered on locked, kept-placement, prepared or decorative parts, and a round part with no flat side is told to get a flat base first. The app remembers the purpose and prepares a rotated STL with its geometry and dimensions preserved. **Upload Model** runs presigned upload + confirm. Estimate the prepared copy with material and quantity.
   The next action stays in a fixed bar while you scroll: **Upload Model → Get Estimate → New Order Draft…**. Without a platform, the bar offers **Create Platform…** when the account has none, or **Choose Platform…** (in Settings) when it has some. Material and quantity are in **Print configuration**, below the preview and mesh check and above the optional geometry tools; the **Material** menu lists every material grouped by type, with out-of-stock ones labelled. Missing materials and invalid quantities link back to the configuration; previous estimates are labelled when settings change. Slant files each upload under its name: an upload with the same name as a file already in your Slant files reuses that file's record and storage (seen on 30 Oct 2026), so it would most likely replace that file's contents for every draft that uses it. So before **Upload Model**, **Upload Again…** or **Upload from URL…** sends anything, Plinth checks your Slant file list (it reads the whole list from Slant first, read-only, every time; if that fails, or Slant's rate limit is nearly used up, it doesn't upload and says to upload again in a moment). When the name is taken, including by this model's own earlier upload, it asks first: **Upload as “Name 2”** keeps the earlier file as it is, **Replace File** replaces it for every draft that uses it, and possibly for orders not yet printed (if that upload fails partway, Plinth says the file may now hold part of the model, unlinks every model in your library that used it, and asks you to upload them again before using them in an order), and **Cancel** is the default. **Upload Again…** asks once: that question, or, when the name is free, whether to upload it as a new file. Names are compared ignoring case, extra spaces and a .stl, .obj or .3mf ending; a model already uploaded is checked under its Slant file's name. As a last check, Plinth stops before sending any bytes if Slant offers to store the upload in a different file you already have. If Slant doesn't confirm an upload (a timeout, a server error or an unclear reply after the file was sent), the bar says the file may already be in your Slant files and offers **Refresh**: if it's listed, select it to estimate and order; if not, **Upload Again…** asks first, because Plinth can't remove a duplicate from Slant. A prepared copy whose saved material differs from the current selection offers **Use Prepared Material** under the material picker; the selection never changes on its own.
   **Compare Estimates…** appears under the quantity once the model is uploaded and materials are loaded. It prices up to 4 in-stock materials (grouped by type) at up to 5 quantities side by side — by default the current material at 1, 5, 10, 25 and 50 — sending at most 20 estimate requests one at a time, only after you press **Get Estimates**; **Stop** or closing the sheet cancels the rest, and nothing is retried automatically. Each cell shows the print-cost total and the price each (total ÷ quantity, including any surcharges), with the lowest per unit marked in each column; delivery is priced later, in the order draft. **Use** sets that material and quantity in Print configuration and keeps the estimate as the current one. Pacing and rate-limit stops are described in [docs/API_REFERENCE.md](docs/API_REFERENCE.md).
   **Get 3DAPI Quote…** (in Print configuration, or in the next-action bar while 3DAPI is the print service, once a 3DAPI key is saved in Settings) prices a library model on 3DAPI, a separate print service, and sets it beside what Slant charges; see [Printing with 3DAPI](#printing-with-3dapi).
   The **…** (More) menu beside the model’s name holds the same items as the model’s context menu in the library, with destructive ones last: for a local model **Rename…**, **Export…**, **Save as Product…**, **Upload Again…** (once uploaded) and **Remove from Library…**; for an uploaded model **Show Local Copy** (when linked), **Copy ID**, **Hide from List** or **Show in List**, and **Delete from Slant…**, which asks first. Renaming changes the library name and later upload names; Slant cannot rename a file that is already uploaded. **Export…** saves a copy (for a slicer or CAD tool) under the model's name; the library file is never moved. Uploaded models that are also in the library show **On this Mac** and offer **Show Local Copy** before downloading another copy.
   **Upload from URL…** (the Import Model menu in the toolbar, or the File menu) asks Slant to fetch a model from an https link straight into your Slant account, on your current platform; it isn’t added to the library on this Mac, and a name already in your Slant files gets the same question as an upload. Slant has dropped this request from its published API, so if Slant no longer accepts it the sheet says so: download the file and add it with **Import Model…** instead. If Slant doesn't reply clearly (a timeout, a server error or an unreadable reply), the sheet says the model may already be in your Slant files: refresh and look for it before uploading again. Creating a platform says the same (use **Reload Platforms**); neither is ever retried.
   STL and OBJ files carry no units. If a model's largest dimension is under 3 mm, a notice suggests it may have been exported in inches, centimetres or metres; models larger than the 220 mm build volume are flagged on the preview instead. For a plain import, **Save Scaled Copy** offers only factors whose result fits the build volume (for example ×25.4 for inches). The copy is a binary STL, parsed and checked before it is added; the original is unchanged. Prepared or edited copies are not rescaled.
   OBJ and 3MF files get the same preview, dimensions and build-volume check as STL, and upload unchanged. OBJ polygons, including concave ones, are split into triangles on their own plane; textures, normals and materials are ignored. 3MF previews apply the file’s unit and every object placement, and ignore colours, paint data and plate settings; when a file places several objects, a note says the whole file is uploaded, so check the estimate covers them all. The **Improve for printing** tools work on STL, so an OBJ or 3MF model shows only a notice with **Save STL Copy**, which adds a separate STL copy (several objects become one mesh) and leaves the original untouched. An OBJ face that crosses itself can’t be converted exactly, so that file offers no STL or scaled copy. Size limits are listed in [docs/API_REFERENCE.md](docs/API_REFERENCE.md).
   Under the preview, a one-line **mesh check** of the model's surface (STL, OBJ or 3MF) reads “Mesh check: Closed, 1 part” when it is watertight, or gives the number of notes. Notes about open edges (gaps), edges shared by more than two faces, flipped or inward-facing faces, separate parts and zero-area triangles, with what each may mean for printing, are in a collapsed disclosure. Zero-area triangles alone don’t count against a model, and a 3MF whose objects are one part each is reported as “one per object”. It welds identical coordinates, runs in the background up to the 500,000-triangle preview limit, and is cached per file version for the session. It is advisory and never blocks upload; fix reported problems with **Repair & Save Copy** (below), in your CAD tool or with a mesh repair tool. Library rows show a small rendered thumbnail of each STL, OBJ or 3MF model, falling back to the cube icon while it renders or when a file can’t be read.
   **Repair and simplify** (under **Improve for printing**): **Repair & Save Copy** joins nearby vertices, removes zero-area, repeated and loose triangles, turns faces the right way (an inner cavity keeps facing inward), closes holes of up to 128 edges and drops tiny loose fragments, then saves “Name (repaired)”, or says there was nothing to change. **Simplify & Save Copy** reduces the model to the number of triangles you type (20,000 by default, the most Reinforce and Auto-improve accept; at least 100) and saves “Name (simplified)”. Neither saves a copy that would fail the mesh check when the original passes it. Auto-improve and Reinforce take up to 20,000 triangles; above that they say so and point to **Simplify & Save Copy**. **Size and base** (once the preview has loaded): **Scale to Size…** scales evenly so the longest side, width, depth or height is the size you type, and saves “Name (scaled to 50 mm)” (“… wide”, “… deep” or “… tall” for one axis) only if it fits the 220 mm build volume; **Add Flat Base…** cuts the bottom level by the amount you choose (it suggests the smallest cut, at most 5 mm, that gives a usable flat contact) and saves “Name (flat base)”; **Add Plinth…** joins the model to a round or rectangular plinth whose bottom edge has a 0.5 mm chamfer, so the first layers' slight spread stays within its outline, and saves “Name (plinth)”. The base tools aren't offered on a copy locked to Z up. **Check Wall Thickness** reports how much of the surface is under 1 and 2 mm thick and any small thin features; it is a guide, not a strength rating, saves nothing and never blocks upload. **Make Fit Coupon…** saves a small “Name (fit coupon)” piece cut from the model so you can order it (for example with **Order a Sample to Me…**) and check a fit before ordering the full part: pick a round hole through the base, a pin or post, a round hole running sideways (hinge, axle or pin holes), or a bottom slice of the whole footprint 1–20 mm tall. The piece always keeps the model's bed face and the way up it prints, is at least 3 mm round the feature and about 20 mm across where the model allows, must be one closed solid, and is previewed before saving; features nearest the bed come first, and pieces over 20 mm tall get a note; hole lists name each hole's height above the bed. Cut it from the print-ready copy so it has the same placement and changes. It checks only that the piece is one sound solid, nothing about fit. Coupons are saved locked the way up they print. These tools run on this Mac and send nothing.
   **Remove from Library…** moves the library's copy of the model to the Trash under the model's name and removes the entry; **Edit › Undo** restores both during the same session, as long as the file is still in the Trash. Finder’s **Put Back** returns the file to a `Removed` folder inside Plinth’s support folder, not to the library: use **Edit › Undo** in the same session, or import the file again. Uploaded files in your Slant account are never deleted by this.
   For uploaded models, **Model analysis** shows Slant's production notes for the file when its team has added any, along with the reported metrics (including whether the part needs supports and the support volume estimate) and the upload and update dates when Slant provides them. Until Slant has measured an upload, **Check Again** reads that one file once; nothing checks by itself. Slant sometimes never measures a file, so after about an hour Model analysis says Slant hasn't measured it since it was uploaded, rather than that it is still analysing, and suggests uploading a fresh copy. Slant stores a 3MF upload as an STL it converts itself, so **Download into Library** of a 3MF upload gives that STL, without the 3MF's units or source and licence details.

   A model's More menu (and its context menu) also offers **Export Listing Images…**, square 2000 px PNG renders from up to six views in a material's colour, saved to a folder you choose without replacing existing files, and **Copy Listing Details**: size in mm and inches, the material, Slant's weight, and suggested production-partner wording for Etsy to edit (the material only for the selected model, whose print configuration it comes from; the confirmation says to edit the wording). **Order a Sample to Me…** on an uploaded model opens a draft of one unit, in the current material, to your own saved address (see Settings), for you to review, create and pay as usual. When several library models share a name, the library and pickers add a detail such as the format or date to tell them apart; material names show in title case (PLA Black), while Slant still receives its own values.

   A 3MF that names its designer, licence, source or copyright shows them in **Source and licence** under the mesh check, as the file's creator or exporter wrote them (plain text, never links); STL copies, prepared, reinforced, improved and scaled copies keep the original's details. When the licence reads as non-commercial (such as CC BY-NC or "personal use only"), or as no-derivatives on a copy Plinth has edited, it says “This licence may not allow selling prints. Check before listing.”, and the same advisory appears in **Copy Listing Details**' notice (never in the copied text) and in **Export Listing Images…**. It is a reminder from the file's own text, not a legal check. Drag a model from the library (**On this Mac** rows) to Finder, a slicer or a message to hand over a copy named after the model, in its original format; the copy lives in a temporary folder that Plinth removes after 24 hours and when it quits or next launches, the library file is never moved, and dropping such a copy back on Plinth is ignored.

   **Personalise from Template…** (File menu or the Models Import menu) opens an OpenSCAD `.scad` template, shows its Customizer values (such as a name), and generates an STL with OpenSCAD installed on this Mac, or with Slant (the template and values are sent to Slant; 5 generations an hour, never retried). The STL is checked and saved as a new library model named after the template and its text values; nothing is uploaded. Values are kept only while the sheet is open.
3. **Orders** — draft with delivery details and line items. The initial shipping country follows your Mac’s Region setting and stays editable; delivery details reused in the current session take priority. If the region cannot identify a country, choose one explicitly. The country menu lists common shipping countries first, then every other country, named in your Mac’s language; it comes first in the address because it decides whether a state is required and how the postal code is checked. When a new draft reuses this session’s last address, it says so (“Same address as your last draft: Ada Lovelace, London”) with **Edit** and **Clear**. **Paste Address…** in **Deliver to** takes an address copied from Etsy, Shopify or an email (it starts with the clipboard's text, read only when you press it, and up to 2,000 characters are read) and shows what it found — name, email, street, apartment or building, city, state, postal code (kept exactly as written) and country — for you to check; phone numbers are ignored, and lines it couldn't place are listed. **Use These Details** replaces the whole address, including any old unit number, keeps the current name or email when the paste has none, and leaves a country it can't recognise for you to choose; if the form already has details or a country you picked, it asks first (**Keep Current Details** is the default). The pasted text is never saved. If the clipboard doesn’t hold something that looks like an address, nothing is pasted, and **Use These Details** stays unavailable until the text has a town or postcode and no long unbroken token or link. **Advanced** under More options holds the shipping provider, a payment service ID and **Reference fields (metadata)**; it opens by itself when a duplicated order copied a shipping provider. The Owner ID sent with drafts is set in Settings › Advanced. **Create Draft** always takes a click: Return never creates a draft, and if Slant refuses it the form says why. **Review & Place Order…** charges and starts fulfillment. Cancel requests follow Slant’s cancel/refund rules; Slant doesn’t cancel drafts, which cost nothing unless placed, so drafts have no Cancel. If Slant refuses a payment or cancel, the review says why; if Slant doesn't answer clearly, the review says what happened (such as no reply in time, or the HTTP status) and that the order may already be placed or cancelled, with **Reload Order** to see what Slant shows. Placing reports “Order placed.” only when Slant shows the order as placed: if Slant accepts the payment but shows the order as cancelled or in a status Plinth doesn’t know, the review says so and closes with **Close**, offering no next draft. When the draft's marketplace order already has a placed order, or another loaded draft is for it, the review warns “Possible duplicate: …” (advice only; Pay works the same). Quitting while Plinth is still waiting for Slant to answer a payment, cancellation, new draft, upload or Import Orders draft asks first (**Don’t Quit** is the default), because Plinth couldn't record the outcome.
   To reorder, choose **Duplicate as New Draft…** in an order’s details or the orders list’s context menu. Plinth reloads the order and opens a new draft with its items, materials, quantities, delivery details, platform and shipping provider for you to check. Items without a model, component or stationery ID are listed as not copied, as is a quantity that isn’t a whole number (set to 1 for you to check). An address country Plinth can’t recognise is left for you to choose, and if the order’s platform is no longer in your platform list, the draft says it uses your current platform. Old prices are never reused: Slant prices the new draft when you create it, and placing it uses the usual charge review. Duplicating is unavailable while that order’s last payment/cancel outcome is unknown.
   Item options copied from the original order (for example slicer options) are listed under each item as **Copied options — sent with this item**; **Remove Options** sends that item without them.
   For the US, Canada, the UK, Ireland, Australia, New Zealand, Germany, France, the Netherlands and Japan, a postal code that doesn’t match the usual format shows a warning under the field once you leave it, or while typing once it is long enough to judge. It never blocks the draft, and other countries get no check.
   Without a default platform, the Orders toolbar says so and offers **Choose Platform…** (Settings › Account), or **Create Platform…** when the account has none. The **Status** menu in the Orders toolbar reloads the list with that status straight away; **Dates & Sort** holds the date range (whole days on this Mac's calendar) and Newest/Oldest (the only way to start from your oldest orders). If orders change on Slant while you load more, a note under the list offers **Reload**. The list starts in the Newest/Oldest order chosen there; clicking **Created** or **Total** sorts the loaded orders by date or amount. With a default platform, the list shows only orders on that platform (and any that don't say which they're on): Slant's list can't be relied on to filter by platform, so Plinth checks each order's platform itself, and a note under the list says how many orders on other platforms it isn't showing. Typing in the search box filters the loaded orders (by recipient, order number, item or marketplace reference); Return looks up an order number among all your orders on Slant (`SLANT_…`, or just its digits), and clearing the box returns to the list. When a status or date filter leaves the list empty, it says which, with **Show All Orders**; if Slant has more pages, it says none are on the pages loaded so far and **Load More** stays under the list. Statuses are Slant's: Draft, Submitted (paid, waiting to print; hover over it in an order's details), Printing (in production), Shipped and Cancelled. A note under the list says which you’re seeing. Slant’s order status can lag its own shipping record, so while an order is Submitted or Printing and its shipping record says it shipped, Plinth shows **Shipped**, with a note such as “Slant’s shipping record says Shipped, but Slant hasn’t yet updated this order’s status from Printing.” Such an order isn’t marked late, hides production progress, offers the after-delivery problems in **Report a Problem…** and words **Cancel…** as **Request Refund…**. Slant’s own status still decides whether Cancel is offered, what counts as spend and how payments are checked, and Slant’s **Status** filter lists such orders under Printing or Submitted (the list says so). A cancel stops if the shipping record or tracking changed after you opened its review. In an order’s details, **Cancel…**, **Duplicate as New Draft…** and **Review & Place Order…** sit directly under the header. Orders being made or shipped show **Tracking** above the costs; drafts and cancelled orders don’t, unless Slant returned tracking details. Order details also show when the order was placed and last updated, the shipping provider and any delivery instructions, when Slant returns them. **Export Orders…** (in the Orders toolbar’s **…** (More) menu, or **File › Export Orders…** on Orders) saves the orders currently in the list (after search, status, dates and platform) as a CSV file: order number, created, status, items, costs, total, currency, carrier and tracking numbers. Columns Slant didn’t return for an order are left blank. Only loaded orders are exported; when Slant has older ones, the save panel says so.
   **Saved Products…** (in the Orders toolbar’s **…** (More) menu, or the File menu) keeps products you sell often: a name, an optional SKU (unique, ignoring case) and their items — library models with a material, components and stationery, each with a quantity per unit sold or **Once per order** (the default for stationery, such as a packing slip). **Save as Product…** in a library model's **More actions** starts one from that model and its prepared material, if it has one. In a draft, **Add Saved Product…** adds a product's items for the number of units sold (2 units of a product with 3 prints adds 6) after any items already there; it shows exactly what it will add, such as “Adds 6 × Bracket, 1 × Packing slip”, and Return adds it. A product can be saved before its model is uploaded, but it can't be added to a draft until the model is uploaded, its material is in stock and every item is still offered; Plinth says what to fix. A model uploaded again is used in its latest upload. The SKU is sent with each item, and is how **Import Orders…** matches a marketplace order's items to the product.
   **Check Cost…** (Saved Products' bottom bar or a product's context menu) prices one order of the product for the **Units in order** you type (1 to 10,000): a fresh Slant estimate for each print, sent one at a time only after you press **Check Cost** (at most 20, never retried; **Stop** or leaving cancels the rest), plus catalog prices for components and stationery (Catalog loads Components and Stationery the first time you open them). It shows the cost per unit and per order before delivery, says which parts it couldn't price and why (including components and stationery Slant marks as not available), and adds a hint of what Slant charged on average to deliver loaded orders with this product to their most common country. Results last only while it is open and are never saved with the product. A print item can also be linked to an OpenSCAD template with **Personalise from Template…** in the product editor: choose the `.scad` file and the text value (**Buyer's text goes in**) that receives each buyer's personalisation, for **Personalise with OpenSCAD** in Import Orders. One item per product can be personalised, not a once-per-order one; Plinth saves only the template's location and the value's name.
   If **Create Draft** times out, loses its connection or gets a server error, Slant may have created the draft anyway. The draft form then names that attempt’s recipient and time — “Your Create Draft for Ada Lovelace at 2:32 PM didn’t get a clear answer from Slant, so that draft may exist. Check your drafts (Orders toolbar › Status › Draft) before creating it again.” — in this form or a new one, for the rest of the session. The next **Create Draft** for the same recipient name then asks you to confirm with **Create Anyway** (**Don’t Create** is the default); so does any Create Draft while an unconfirmed attempt had no recipient name, once older attempts have dropped off the list, or when the new draft has no recipient name. A draft for someone else is created without asking, though the notice stays. If several attempts went unconfirmed, the notice lists each one. The recipient names and times are kept in memory only, for the rest of the session (changing the key doesn’t clear them). An attempt clears once a draft for the same recipient name is created successfully (a draft for someone else leaves it listed), or once **Look for Draft on Slant** in the notice finds that attempt. Recipients are matched by name only (ignoring case and spacing), so two customers with the same name share one warning: a confirmed draft for one clears the other's attempt too. Each draft Plinth creates carries a hidden reference (`studioDraftId` in its metadata), and **Look for Draft on Slant** looks for it, read-only, among your 300 newest orders, offering **Show Order** when found. Not finding it never clears an attempt, since the draft may be older than the orders read; an attempt made with all 10 reference fields in use carries no reference and can't be looked for. The notice lists the newest 5 attempts, and still warns about older ones after they drop off. A definite refusal from Slant doesn’t clear it, because it says nothing about the earlier attempt. Draft creation is never retried automatically, and the error alert offers no **Try Again** for it.
   Order details show the marketplace order number with a Copy button when the order’s metadata has `sourceOrderId` (and `source`: “Etsy order”, “Shopify order”, or “Imported order” for Plinth’s order template), if Slant returns metadata. The orders list shows it under the recipient, such as “Etsy order 3141592653”, and searching the list matches it.
   **Profit check** (collapsed under an order’s costs) estimates what you made on that order: enter what the buyer paid for the items and shipping, in US dollars, and choose marketplace fees — None, Etsy (US), Shopify Payments (US Basic) or Custom. It subtracts the fees and the order’s real Slant total (print + delivery) and shows each line, the estimated profit and the estimated margin. Etsy and Custom fees also ask for **Units sold** (default 1): the listing fee is charged per unit the buyer bought, which isn’t the number of items in the Slant order (a unit can need several prints and a packing slip). The preset rates are assumptions checked in October 2026 (Etsy: 6.5% transaction fee and 3% + $0.25 payment processing on item + shipping, $0.20 listing renewal per unit sold, optional 15% Offsite Ads capped at $100; Shopify Payments Basic: 2.9% + $0.30). The rates in use are shown as one dated line, such as “Etsy (US): 6.5% transaction + 3% + $0.25 processing + $0.20/unit listing · checked October 2026” (“your rates” once edited); **Edit rates** opens every rate for editing (it stays open while you type, and opens by itself for an empty Custom preset or a rate that needs fixing), so check them against your own account. If you sold in another currency, convert to USD yourself. Not included: taxes, refunds, ads you pay for separately and currency conversion. Without a usable Slant total (or for cancelled orders) it explains why instead of showing a number. For a draft that Import Orders created this session from an Etsy or Shopify order in US dollars, what the buyer paid for the items and shipping (never taxes) and the units sold are filled in from the import, with a caption naming the order (“From the imported Etsy order … (this session only)”) and any notes, such as a refund it doesn't take off; edit them if they differ. If you left some of the order's items out of the draft, only shipping is filled in. These amounts stay in memory until you quit, disconnect or change your API key. Only the fee preset and rates are remembered; what the buyer paid and the units sold are never saved.
   **Import Orders…** (Orders toolbar or File menu) turns a marketplace CSV into order **drafts** for you to review: Etsy’s “Sold Order Items” download, a Shopify orders export, or Plinth’s own order template (**Save Template…** writes the columns with one example row). Comma, semicolon and tab files are recognised, including Excel’s `sep=;` first line. Each line’s SKU must match a saved product, which supplies the items, material and quantities; matching ignores case and surrounding spaces. Rows of one order with the same product are added together, so each product is expanded once for its total units (at most 10,000), and a once-per-order item that several of the order’s products share — the same packing slip, say — is added once. Items with an unknown SKU, or no SKU (then they’re listed by item name), appear once each under **Match products**, with a one-line list of the unknown SKUs and **Copy** so you can set them up in Saved Products. For each you can choose a saved product, or **Leave out of drafts** (for things like Shopify shipping protection); the choice applies to every order with that SKU or name, is never guessed, and lasts only until you choose another file or close the sheet — it isn’t saved. The preview lists one row per order with its recipient, country, the items its draft will contain (including stationery) and any problems. Orders that can’t be imported (an unknown SKU you haven’t matched, missing address fields, an unrecognised country, a missing state for the US, Canada or Australia, a quantity that isn’t a whole number, rows of the same order with different delivery details) can’t be ticked. Orders that need a second look start unticked: already shipped, cancelled or refunded on the marketplace, a Shopify shipping company (Slant drafts have no company field), a US ZIP with fewer than five digits (choose the zero-padded ZIP for that order if a spreadsheet dropped its leading zero; Plinth never pads on its own), or one that looks already imported. Etsy files have no buyer emails, so orders without one need **Email for orders without one** (for example your shop’s); Plinth never invents one. **Create N Drafts…** asks for confirmation (Return cancels it), then creates drafts one at a time, at most one a second, waiting for Slant’s rate limit when needed. Nothing is charged: each imported draft is then reviewed and paid one at a time through the existing charge review in Orders. A draft Slant refuses is reported and the rest continue; if Slant doesn’t confirm one (a timeout, connection loss or server error), the import stops at once and marks it as possibly created — check your drafts before importing it again. Requests are never retried. **Stop**, or closing the sheet, takes effect before the next request. Afterwards the orders list reloads showing drafts (the toolbar’s **Status** menu set to Draft), and **Show Drafts** closes the sheet to show them. Each draft’s metadata records `source`, `sourceOrderId` and Plinth's draft reference (`studioDraftId`); Shopify orders also record which line items or SKUs the draft covers (`sourceItems`), and fetched ones the store (`sourceShop`), for **Send Tracking to Shopify…**. Orders already imported this session, or found in loaded orders’ metadata, start unticked; older orders that aren’t loaded aren’t checked, and the sheet says so. If a draft wasn't confirmed, **Look for Draft on Slant** in the sheet checks your newest orders read-only and, when it finds it, marks that order as imported. Changing the key or platform stops the batch before the next request. Etsy and Shopify sale amounts in US dollars are kept in memory for the Profit check (other currencies aren't used, and the sheet says so); they are never sent to Slant.
   With Shopify connected in Settings, **Fetch from Shopify** (beside **Choose File…**) reads your store's paid, unfulfilled, open orders from the last 60 days (up to 250, at most 30 items each) straight into the same sheet, with the same checks, matching and confirmation; **Stop** or closing the sheet cancels the fetch, and nothing is sent to Slant until you create the drafts. On Shopify's Basic and Starter plans apps don't get customers' names and addresses, so the sheet suggests exporting a CSV from Shopify admin instead.
   **Personalise with OpenSCAD** (collapsed; it appears when an order's product has an item linked to a template in Saved Products) makes each buyer's model with OpenSCAD installed on this Mac — never Slant's generator, which allows only 5 an hour. For each product, choose which part of the buyer's personalisation goes into the template (a labelled part such as “Name”, the whole text, or **Don't Personalise**, the default; never guessed). When you create the drafts, Plinth makes all of an order's models, checks that each is a closed, uploadable STL, uploads them to your Slant files named by the Etsy or Shopify order number (or “Personalised model”; never the buyer's text or name) plus a short random code, such as “Etsy order 123 personalised · 7f3a9c21”, so one order's model never replaces another's, and uses them in that order's draft. They aren't added to your library, the choices aren't saved, and temporary files are removed. An order whose model can't be made or whose upload is refused is skipped; if Slant doesn't confirm an upload, the import stops with that order's draft unsent (check your Slant files before importing it again). Nothing is retried.
   Cancel or Escape closes an untouched draft immediately; once you’ve changed items, delivery details, platform or shipping provider, or typed reference fields (metadata) or a payment ID, Plinth asks before discarding them. A quantity of 25 or more shows a “check for an extra zero” note under the Models quantity field and in the draft, and is highlighted in the charge review; it doesn’t block the order. If Slant's order lists a cost Plinth doesn't add into its total (a tax or fee field, say), or Slant's own total differs from print plus delivery, the charge review says so — “Slant also lists taxCost, which this total may not include. Check the order on Slant before paying.” — without changing whether you can pay; if such a field appears or changes after the review, the payment isn't sent.

   While Plinth is open it checks your newest and most recently updated orders every few minutes and reports changes to those on the default platform (**Settings › Advanced › Order updates**; on by default), so an older order that ships is noticed too. If Slant refuses the key or asks Plinth to slow down, the checks pause and that section says so. Orders then shows **Since you last looked**, for example “2 shipped · 1 cancelled”, with **Show** (reloads and lists those orders, also reading up to 10 changed orders that aren't on the first page) and **Dismiss**, and the sidebar badges cancellations and shipments; Slant's re-labelling of earlier statuses, such as Queued now reading Printing, isn't reported as a change; **Show count on Dock icon** (on by default) puts the same count on the Dock icon. When orders have shipped, the banner links to **Tracking for Your Shop…**. Show counts a change as seen only once its order is in the list. Turn on **Notify me about order changes** for macOS notifications, which show only the order number and status; clicking one brings Plinth forward and opens that order, waiting until any open sheet or dialog closes and no request is running. Only each order's ID, status and when it was seen are saved; **Forget Saved Statuses…** removes them, and they're forgotten when you change the default platform or disconnect. While 3DAPI is the print service these checks pause, and the Dock count is cleared; choosing Slant 3D again reports what changed meanwhile (see [Printing with 3DAPI](#printing-with-3dapi)).

   **Slant API changes.** Slant doesn't announce changes to its API (on 26 Oct 2026 it replaced its order statuses without notice), so Plinth checks for itself. While a Slant account is connected, about a minute after launch if a day has passed since the last check and then once a day (or when you press **Check Now**), it downloads Slant's public API description (`https://slant3dapi.com/v2/api/openapi.json`) and compares it with the copy this version of Plinth was made with, ignoring wording, titles and examples, and the description's own details (such as its name and list of sections), apart from its version number. It also notes, for the session, order statuses in Slant's replies that it doesn't recognise, and order lists it couldn't read. If something differs, Orders shows a notice, such as “Slant changed its API on 3 Nov 2026 (Orders), after this version of Plinth was made. Plinth carries on as before, but some details may be missing or wrong until it's updated. If anything in Orders looks odd, check it on Slant.”, with **Details…** (Settings › Advanced › **Slant API**: what changed, when it last checked, this session's unrecognised statuses and **Check Now**) and **Dismiss**. Dismiss hides an API change until Slant changes the API again (a wording-only edit doesn't bring it back), hides the unrecognised statuses shown even after relaunching (a different status still shows the notice), and hides an unreadable order list for the session. A Plinth update starts afresh. Orders with a status Plinth doesn't recognise are treated with caution: Plinth offers no Cancel for them, leaves them out of the Spending Report, never marks them late and doesn't treat them as placed. The check only informs you: Plinth never changes how it works, and never blocks paying, cancelling, creating drafts or uploading, because of it. There are no notifications, badges or alerts.

   **Needs attention (loaded orders)** in the Orders toolbar's Status menu shows only loaded orders past the end of their arrive-by day (on this Mac) and not shipped yet, not shipped 5 days after being placed, or drafts not placed after 2 days (drafts over 30 days old are ignored); a marker in the Status column says why. An **Arrive by** column appears when Slant returns arrive-by dates. **Tracking for Your Shop…** (the **…** menu or File menu) lists loaded orders Slant has tracking for, imported marketplace orders first and then other orders, with the tracking number, the provider Slant reports, and **Copy Tracking** / **Copy Order & Tracking**; mark an order as done once you've added its tracking in your shop (marks last until you quit; **Show Marked Orders** lists them again). **Export Shopify Tracking CSV…** there saves order name, tracking number and company for imported Shopify orders, for a bulk-fulfilment app, with no names or addresses. With Shopify connected, **Send Tracking to Shopify…** there adds Slant's tracking to imported Shopify orders (up to 50) and marks as fulfilled only the items Slant made; anything else in the order stays unfulfilled. It first checks each order, read-only, and skips any already fulfilled or carrying this tracking, any from another store, and any where Shopify doesn't show enough unfulfilled units of the draft's items. Orders imported from a CSV file are matched on the recipient's name and postcode and are never ticked for you. **Email customers their shipping details** is off by default and remembers your last choice. **Send Tracking for N Orders…** asks first (Return cancels), then sends one order at a time, checking each again just before; it is never retried and stops if Shopify doesn't confirm one, since Plinth can't undo a fulfilment. **Spending Report…** (the **…** menu or File menu) shows Slant spend per month and top items by units, leaving out drafts and cancelled orders, plus **Average printing cost per product** (Slant's price per print, from orders whose item prices add up to their printing cost; products with one print and a SKU are grouped by SKU, so a re-uploaded model stays one product) and **Delivery by destination country** (orders, average and lowest–highest, as a guide for your Etsy or Shopify shipping profiles). It uses the loaded orders, or choose a **Period** (this month, the last 3, 6 or 12 months, this year or last year) and **Load the Whole Period** to read every order created in it, one page at a time (up to 5,000 orders); either way it counts only orders on your default platform (and any that don't say which they're on); those stay in the report and don't change the Orders list. Copy it as text or export it as CSV; amounts are what Slant charged, in US dollars.

   **Pay Several Drafts…** (the **…** menu) pays up to 20 drafts after one review. Tick drafts from the list (none start ticked; **Select All** takes the first 20), then **Review N Drafts** loads each one fresh from Slant and shows a card per draft: items (large quantities flagged), printing, delivery, total, recipient, the marketplace order and, for drafts imported this session, the estimated profit, with a notice when an order would lose money. Drafts that can't be paid are listed under **Not included** with the reason: no longer a draft, a payment or cancel result still unknown, a cost Slant lists that Plinth doesn't add (pay it in its own review after checking), a second draft for the same marketplace order (only the first is included, and none at all when any draft for that order was left out for another reason; Shopify drafts that cover different items of one order, or another store's order with the same number, aren't duplicates), or one whose marketplace order already has a placed order in the list. If a draft created this session wasn't confirmed, the review warns that a duplicate may exist. **Pay N Orders (Total $X USD)** isn't the default button and has no shortcut, and its confirmation defaults to **Don't Pay**. Plinth then pays one order at a time, checking each again just before paying it, and stops at the first that changed, was refused, didn't confirm or wasn't placed; nothing is retried. It won't start or go on while any order's payment or cancel result is unknown (it names that order), or if the drafts, total, key or platform changed since the review. **Stop**, or closing the sheet, takes effect before the next order. Afterwards each order shows its result, with **Reload Order** for any that didn't confirm.

   Placed orders show each item's estimated print completion when Slant provides it, and say which address the shipping label was made for when it differs from the order's. **Report a Problem…** offers the problems that fit the order's status (late while it's being made or shipped; damaged, wrong, missing or a print defect once shipped; Other always) and puts together a message about the order (number, status, items and tracking; no names or addresses) to copy into your message to Slant support (support@slant3d.com, as its caption says; Plinth sends nothing itself), and offers **Reprint as New Draft…**. After placing an order, **Review Next Draft** opens the review for the next draft in the list as it was when you started (re-sorting or filtering meanwhile doesn't move it), and **… › Review Drafts One by One…** starts at the first; each draft is paid only when you press Pay in its own review. Each review in the run shows its place (“Draft 2 of 5”) and **Skip to Next Draft…**; after **Go Back** the order offers **Review Next Draft…** and **Stop Reviewing**. Import Orders shows each item's personalisation (Etsy's personalisation, or a fetched Shopify item's properties) with **Copy** and **Copy All Personalisation**; it isn't saved or sent with drafts, which use the saved product's model unchanged unless you personalise them with OpenSCAD, so an order with personalisation otherwise says “This draft uses the plain model. Make the personalised one first.” and starts unticked.
4. **Developer tools** — turn on **Settings › Advanced › Show developer tools** (off by default) to add a **Developer** section to the sidebar and Go menu with the **API Workbench** (every catalog operation against production, with parameter validation, JSON bodies, mutation review, typed confirms for high-risk deletes/secret rotation, and secret redaction in responses) and **Activity** (the session’s request history; it is recorded whether or not it is shown). The switch waits while a request runs or a sheet, alert or dialog is open, so a Workbench review or request is never cut off; turning it off on a developer screen moves you to Models.

Live traffic uses the **production** API. Mutations are never auto-retried. If a network error leaves a charge or cancel outcome uncertain, Plinth locks that order across Orders, Pay Several Drafts and the Workbench until you reload it and the result is clear. If the status still hasn’t changed, check the order in your Slant dashboard; the lock lasts for the session. For a cancel, a move from Submitted or Printing to Shipped doesn't count as the result: an order being made ships whether or not a refund was asked for, and that is often only Slant's status catching up with its shipping record. The order's review then says it has shipped since and to check it in your Slant dashboard, and the lock lasts until a reload shows the order cancelled (or any other change), or you quit. While any order is locked, **Pay Several Drafts…** loads nothing and names that order. A definite refusal from Slant (an HTTP 4xx other than 408/409, such as a declined payment) means nothing is pending, so the order stays unlocked.

### Shopify connection

Optional: connecting your own Shopify store lets **Import Orders…** fetch orders directly and **Tracking for Your Shop…** send tracking back. Plinth doesn't need it for CSV imports.

1. In Shopify admin, open **Settings › Apps › Develop apps › Build apps in Dev Dashboard** and create an app.
2. Create a version with the scopes `read_orders` and, to send tracking, `write_merchant_managed_fulfillment_orders`, and release it.
3. Install the app on your store, then copy its client ID and secret from the app's Settings.
4. In **Settings › Account › Shopify (optional)**, enter the store's `your-store.myshopify.com` address (custom domains aren't accepted), keep **Sign in with** on **Dev Dashboard app**, paste the client ID and secret, and press **Connect & Test**. The details are saved only once the test passes, and it says which scopes the app has. An Admin API access token (`shpat_…`) from an older custom app made in the store admin works too (**Access token (older custom app)**).

**Test Connection** shows the store's name and plan. Shopify shares customers' names and addresses with custom apps only on its Grow plan or higher; on Basic and Starter, Plinth warns that fetched orders can't be drafted, so export the orders from Shopify admin (**Orders › Export**) and import that CSV instead. Connecting or disconnecting waits while a Shopify task is running or **Send Tracking to Shopify…** is open. **Disconnect…** deletes the details from the Keychain on this Mac; your store and its app are unchanged. Query limits and what is unverified are in [docs/API_REFERENCE.md](docs/API_REFERENCE.md).

### Choosing a print service

**Settings › Account › Print service** chooses who prints your orders: **Slant 3D** (the default) or **3DAPI** ([dapi.digital](https://www.dapi.digital)), a separate print service. The choice changes Models' next steps, the Orders section and Catalog's materials; your model library, the mesh and design tools and **Get 3DAPI Quote…** stay as they are. The two services never share data: no price, ID or file from one is sent to the other. The choice is saved as a preference. It can't change while either service is still answering an order, payment, cancellation, draft or upload, while a 3DAPI order sheet or the **Get 3DAPI quote** sheet is open, while a request runs, or while any sheet, alert or dialog is shown; the picker says why. With 3DAPI chosen and no 3DAPI key saved, Settings says to add one under **3DAPI**, and Models, Orders and Catalog offer **Add 3DAPI Key…** or **Open Settings**.

### Printing with 3DAPI

[3DAPI](https://www.dapi.digital) prints on demand from model files and delivers worldwide except Russia, Belarus, Iran and Syria. With a 3DAPI key, **Get 3DAPI Quote…** compares 3DAPI's price with Slant's whichever print service you choose; with 3DAPI as the print service, Plinth also places, follows and cancels 3DAPI orders. Plinth isn't affiliated with 3DAPI.

**Setup.**

1. 3DAPI needs an **integrator** account ([dapi.digital/integrator/sign-up](https://www.dapi.digital/integrator/sign-up)). A 3DAPI seller account can't quote files, and an integrator account must use an email that has no 3DAPI seller account.
2. In 3DAPI's dashboard, make an API key with **quotes:read**, **quotes:write** and **orders:read** (Plinth won't save a key without them), and **orders:write** if you want to place and cancel orders. **wallet:read** is optional: with it the order review shows your wallet balance, any shortfall and your sample credit. Plinth doesn't need **orders:read_customer**: without it, 3DAPI hides each order's customer, address and notes, so Orders shows only the destination country; with it, Orders shows them (kept in memory only) and **Export Orders…** can include them.
3. In **Settings › Account › 3DAPI**, paste the key and press **Save & Test**. Plinth checks it with 3DAPI and saves it (in the Keychain) only when it belongs to an integrator account with those permissions. The account line shows whether 3DAPI has approved the account and, until it has, how many of this round's quotes you have used; a second line says “Ordering: ready. Each order is charged when you press Place Order.” or why ordering isn't available yet (no **orders:write**, no approval yet, or billing details missing). **Test Saved Key** checks it again; **Remove…** deletes it from this Mac (**Keep Key** cancels). The key can't change while a 3DAPI request runs, a 3DAPI order or cancellation is waiting for its answer, or a 3DAPI order or quote sheet is open. A new key starts Orders and order updates afresh, because it may belong to another account.

Until 3DAPI approves your account (you submit 10 quoted files in 3DAPI's dashboard and people review them, usually in 24 to 48 hours), it allows 25 quotes per round and a daily number that resets at midnight UTC, and none while files are in review; Plinth stops before uploading when files are in review or the round's quotes are used up. Ordering needs the approval and your business billing details (with a tax registration) in 3DAPI's dashboard. On approval 3DAPI gives $15 of sample credit for 30 days.

**Quotes.** **Get 3DAPI Quote…** (for a model whose file is on this Mac: in Models › Print configuration while Slant 3D is the print service, or in the next-action bar while 3DAPI is) opens **Get 3DAPI quote**: choose **Deliver to** (it starts from your Mac's region; with no recognisable region you choose one) and **Quantity** (it starts from Print configuration's quantity), then press **Get Quote**. Plinth first looks for a quote it already has for the same file (from this session, or among your newest quotes on 3DAPI), so the same file usually isn't quoted twice. A quote 3DAPI rejected in review, or one marked ready without a price, can't be used, so **Get Quote** asks for a new one. Otherwise it uploads the file, asks 3DAPI for a quote and checks every few seconds until it is ready (usually a minute or two; after 15 minutes it pauses, and **Check Again** reads it once more). **Stop** stops the checks and can stop the file upload, but a request already sent to 3DAPI to make the upload or the quote always finishes. Stopped while the file is being sent, or before the quote is asked for, no quote is made; stopped while the quote is being made, it still gets made and **Check Again** reads it. Nothing is sent again by itself; if 3DAPI's reply doesn't come back, Plinth looks for that quote first next time and asks before making another (**Don't Quote** is the default). Once the quote is ready Plinth asks 3DAPI for shipping, and **Update Shipping** prices a new country or quantity.

The sheet shows 3DAPI's print price for 1 unit and for your quantity (an upper bound: 3DAPI charges less per unit for larger quantities, and gives the exact price only with an order), shipping with its parcel size, and the total (3DAPI's prices are before VAT, which it adds only for UK and EU businesses without a confirmed VAT number). Beside it: Slant's current print estimate when you have one for this model and quantity, what Slant charged for delivery to that country on your loaded orders for the default platform (average, number of orders and range), and an approximate Slant total at quantity 1. Notes say that the two services print with different printers and settings, which material 3DAPI priced, when VAT or customs may apply, and 3DAPI's stated times (3–5 business days to make, then 1–3 business days locally or 5–10 internationally). The sheet itself orders nothing, and nothing from 3DAPI goes into a Slant estimate or draft.

**Ordering.** With 3DAPI as the print service, the Models bar offers **Get 3DAPI Quote…** and **Order with 3DAPI…**. Get 3DAPI Quote… is the prominent step until this session knows a ready quote for the model's file, then Order with 3DAPI… is (unless 3DAPI says the account can't order yet, which the bar says instead). Order with 3DAPI… opens **New 3DAPI order** in Orders with the model and its quantity; **New 3DAPI Order…** (Orders' toolbar, or **File** ⌘N) opens it empty, and **Order a Sample to Me…** (a model's More menu) with one unit to your saved address. Nothing is charged until you review the order and press **Place Order**.

- **Items:** **Add Model** lists the library models whose file is on this Mac. Each line looks for the model's ready quote (this session's, or among your newest quotes on 3DAPI) and never uploads or makes one: a model without one says to get a quote in Models first, and one still being priced offers **Check Again**. A line shows 3DAPI's price per unit and what the line costs at most; quantities are 1–10,000, and an order holds up to 100 lines. **Use 3DAPI’s suggested materials** is on when 3DAPI suggested a catalogue material for every colour slot; turn it off to choose one of 3DAPI's materials for each slot (3DAPI's suggestion is chosen to start with).
- **Deliver to:** the country first (from your Mac's region, never assumed; countries 3DAPI doesn't deliver to aren't listed), then the name, email (3DAPI requires it, and Plinth never makes one up), an optional phone number and the address. **Use My Address** and **Paste Address…** work as in Slant's composer, asking before they replace details you entered (**Keep Current Details** is the default).
- **Reference and notes:** an optional reference of your own, such as a marketplace order number (letters, digits, `-` and `_` are kept; anything else becomes `-`), and optional notes for 3DAPI (up to 2,000 characters). Plinth never fills either from a buyer's details.
- **Shipping estimate:** priced once every line and the country are set; after a change, **Update Shipping**.
- **Cancel** asks before discarding what you entered (**Discard Order** or **Keep Editing**); when an order you placed from this sheet got no clear answer, the question says it may have been placed and charged, and the warning stays. **Review Order…** always takes a click (Return never opens it) and stays unavailable, saying why, until the order is one 3DAPI would accept, and while **Look for Order on 3DAPI** is looking.

**Review 3DAPI order** reads your account, every quote and shipping again, and your wallet when the key has **wallet:read**. It lists each line's model, materials (for a line using 3DAPI's suggestions, the ones the quote suggests now, which are what 3DAPI prints), quantity, price per unit and “Up to” amount, then shipping (excluding VAT, with its parcel size) and the total as “Up to $… before VAT”: 3DAPI's price per unit falls with quantity, so the exact amount comes only with the order. Notes say when VAT applies and that if your 3DAPI wallet is short, 3DAPI charges the rest to your saved card (with VAT on that top-up for EU and UK businesses without a confirmed VAT number); when the total may be more than your balance, the review says by how much. Materials you chose yourself may change the price, which Plinth can't check before ordering. When your wallet shows sample credit, **Use My Sample Credit** (off by default) spends it first; 3DAPI uses it only for orders to your own country (your billing or sign-up country), otherwise the order is charged in full.

**Place Order** charges your 3DAPI wallet at once and sends the order to production. It is never the default button and has no shortcut or menu item. Just before sending, Plinth reads everything once more: if the account's ordering status, the country, the lines, a price, 3DAPI's suggested materials for a line that uses them, or shipping changed, or the sample credit was changed or is gone, it sends nothing and shows what changed, for you to press Place Order again. It then sends the order once, never again by itself, with a reference made of yours and a code that is new for every press (such as `ETSY-1042_pl3f9a1c2b`, or `plinth_3f9a1c2b` without one), so it can be found again. **Go Back** (Escape) works until the order is with 3DAPI; while 3DAPI is answering, the sheet can't close, and quitting asks first (**Don’t Quit** is the default).

- **Placed:** the sheet closes and Orders shows the order, selected.
- **Refused:** “3DAPI didn’t place the order, and nothing was charged.”, with 3DAPI's reason (for example a wallet that is short with no saved card, a declined card, an account not approved yet, billing details missing, or production paused).
- **Unclear** (no answer in time, a server error or an unreadable reply): the review says 3DAPI may have charged and placed it. Plinth remembers that attempt until you quit (the recipient's name, units, country and time, in memory only, whatever key or service you choose meanwhile) and shows it in Orders and in every composer with **Look for Order on 3DAPI**, which looks for that exact reference without sending or placing anything. An order found is shown and selected, and its warning goes; one not found keeps the warning, since it may still appear. While any attempt is unconfirmed, **Place Order** first asks **Place another order?**, with **Place Anyway** and **Don’t Place** as the default.

**Orders.** With 3DAPI as the print service, Orders lists your 3DAPI orders, newest first, 50 at a time (**Load More**), with their number, status, date, units, country, total and your reference. The **Status** menu shows one of 3DAPI's statuses (Awaiting payment, Paid, Assigned, In production, Shipped, Completed, On hold, Rejected, Returned, Cancelled), the search field finds part of an order number or reference on 3DAPI, and **Refresh** reads the newest orders again; an empty list names the filter or search and offers **Show All Orders** or **Clear Search**. A status Plinth doesn't recognise is shown as such and is never cancelled, counted as spend or treated as placed. An orange marker (and a line in the details) flags an order on hold, rejected, returned or in an unrecognised status, one not in production more than 3 business days after it was placed, and one not shipped after more than 7 (3DAPI says orders ship within 3–5 business days of payment). The details show the status and what it means, when the order was created and updated, your reference and the full reference 3DAPI holds (with **Copy**), the delivery country (and, with **orders:read_customer**, the customer and address), the items (named after your library model when the quote came from it), the charges (items, shipping, VAT, sample credit, total and who paid), refunds, and the parcel size, carrier, ship date and tracking number (**Copy**; 3DAPI gives no tracking link). The actions are **Refresh**, **Duplicate as New Order…**, **Copy Order Number**, **Report a Problem…** and, last, **Cancel Order…**.

- **Cancel Order…** appears only while an order is Paid, before a production partner has it. **Cancel 3DAPI order** reads the order again and goes no further unless it is still in the status you saw; **Cancel Order** (never the default, no shortcut) reads it once more and sends the cancellation once. 3DAPI refunds a wallet order in full to your wallet (a checkout order made outside Plinth goes back to the buyer's card, usually within 5–10 business days). Once a partner has the order, the details say to email contact@dapi.digital. From the moment the cancellation is sent until 3DAPI answers, Plinth offers no second Cancel for that order. If 3DAPI doesn't answer clearly, or answers without showing the order cancelled, it stays that way until a refresh shows the order cancelled or in another status; a clear refusal lifts it at once.
- **Duplicate as New Order…** opens the composer with the same quotes, quantities and colour-slot materials (each quote is read again, since 3DAPI may have rejected it since). The address isn't copied: 3DAPI returns it only as one line, and only to keys with orders:read_customer. An order whose lines weren't read needs **Refresh** first.
- **Report a Problem…** puts together a message for 3DAPI (contact@dapi.digital) from the order's number, status, dates, tracking and items, with the problems that fit its status; **Copy Message** copies it for your email, and Plinth sends nothing. Names, addresses and your reference are left out. 3DAPI asks for photos of damage or print defects, and reprints lost parcels.
- **Profit check** works as for Slant: the cost is what 3DAPI charged you (VAT included) less sample credit and completed refunds, for orders in US dollars that you paid. The fee presets and rates are the ones Slant's Profit check saves; what the buyer paid is never saved.
- **Tools** (the toolbar, or the **File** menu): **Spending Report…** (orders paid from your 3DAPI account, by month, with items, shipping, VAT, credit and refunds and what you paid, and delivery by destination country; **Load the Whole Period** reads up to 50 pages of 100 orders, read-only, with **Continue Loading** after a stop; **Copy as Text** and **Export CSV…**), **Export Orders…** (a CSV of the loaded orders; customer names, emails and addresses only when you tick **Include customer details**) and **Tracking for Your Shop…** (the carrier and tracking number of loaded orders that have one, to copy into Etsy or Shopify, grouped by whether they carry your reference, with **Copy**, **Copy All** and a **Done in your shop** tick that lasts until you quit). They use only the orders loaded for the filter shown. The loaded orders stay when you switch to Models or Catalog and back, until you save or remove a 3DAPI key.

**Order updates.** While 3DAPI is the print service and its key is saved, Plinth checks your open 3DAPI orders every 4 minutes (while **Check orders while Plinth is open** is on in **Settings › Advanced › Order updates**, and never while a 3DAPI order sheet is open, an order or cancellation is waiting for 3DAPI, or any sheet, alert or dialog is shown), with up to 10 further reads of orders that left the open list. It remembers statuses in memory only, so the first check after each launch is silent. An order that becomes shipped, on hold, rejected, returned or cancelled adds to the Orders badge in the sidebar (cleared when you open Orders) and, with **Notify me about order changes** on, sends a notification showing only the order number and status; your own cancellations in Plinth aren't reported. Clicking one brings Plinth forward and, if 3DAPI is still the print service, opens that order once nothing modal is shown; it stays in the list after a refresh, and if it isn't under the Status or search shown, Orders shows every order again (as it does for an order you place or find). Slant's order checks pause while 3DAPI is chosen; when you choose Slant 3D again, they report what changed meanwhile. The Dock count shows Slant orders only.

**Catalog** shows 3DAPI's materials (PLA and PETG colours), grouped by type and searchable. 3DAPI has no catalogue of components or packaging: it ships each order in its own packaging.

**Menus.** With 3DAPI chosen, **File › New 3DAPI Order…** (⌘N) opens the 3DAPI composer (or Settings › Account when no 3DAPI key is saved); **Spending Report…** opens 3DAPI's version in Orders from anywhere, and **Export Orders…** and **Tracking for Your Shop…** theirs while Orders shows loaded orders (as in its Tools menu); **Refresh** (⌘R) reloads the 3DAPI orders list while Orders is shown (and Slant's on the developer screens); **Upload from URL…** and **Import Orders…** are unavailable. No menu item or shortcut places or cancels an order.

**What goes to 3DAPI.** Getting a quote sends the model file exactly as it is (a 3MF can carry its own title and designer) under a neutral name made from the file's contents, never the model's name in Plinth; 3DAPI keeps quoted files, and its API has no way to delete them. Placing an order sends the quotes, quantities and materials, the recipient's name, email, phone (if given) and address, the reference and any notes; 3DAPI keeps them with the order. Questions to 3DAPI and what is unverified are in [docs/3DAPI_REFERENCE.md](docs/3DAPI_REFERENCE.md).

## Design tools (optional)

Three optional tools use outside services with your own keys, and each request is billed to your own account with that service. Plinth works without them.

**Settings › Design Tools** sets them up:

- **Claude (Anthropic)** — an Anthropic API key from the **Anthropic Console**; Anthropic bills your account for each request (Claude Opus 5.5: $4 per million tokens sent, $20 per million written). **Save & Test** sends a tiny real request (well under a cent) and saves the key only if it works; **Test Saved Key** and **Remove…** are there too. The key can't be changed while a Claude request is running or while **Design an Accessory** or **Review for Printing** is open.
- **3D generation (optional)** — choose **Meshy** or **Tripo** and paste that service's key. Meshy's API needs a paid plan (free accounts can't make API keys); Tripo's API is paid for with credits (1 credit = US$0.01). A Tripo key works only on the **Tripo site** it was made on (International or China mainland). **Save & Test** reads your credit balance. The footer summarises each service's plan and licence terms, with links to its pricing and terms.
- **Photo sharing** — before the first photo goes to Anthropic, Meshy or Tripo, Plinth asks once for that service and says what will be sent; **Don’t Send** is the default. Only your answer and its date are kept; **Reset** makes Plinth ask again.

**Design an Accessory** also needs [OpenSCAD](https://openscad.org/downloads.html) installed in Applications.

**Design an Accessory from a Photo…** (File menu or the Models **Import Model** menu) asks Claude to design a part that fits something you photograph, such as a stand or a holder. Add 1–3 photos, say what to make, and type at least one measurement with how you took it (**Calipers**, **Ruler** or **Estimate**): a photo has no scale, so every size comes from these, and Claude allows more clearance for a rough one. Notes are optional. The sheet shows the estimated cost before you press **Start Design** (roughly $1 for a typical design and up to about $2 if Claude uses all its replies). Claude then writes OpenSCAD code, and Plinth renders it with OpenSCAD on this Mac (code that would read other files is refused, and each render is limited to 120 seconds and a memory cap) and sends back its own measurements — size, mesh check, wall thickness, overhangs, flat contact and the fit sizes the code reports — with four pictures. Claude may ask you a question (answer it or **Skip**). Each round allows up to 10 replies and 4 renders, and the running cost is shown as it works; **Stop** ends the round, and **Send to Claude** with a note starts another round of changes. When Claude finishes, **Save to Library** adds “Name (designed)” as a new model, and **Save Template…** saves the OpenSCAD file, whose sizes you can adjust later with **Personalise from Template…**. Check every measurement on a test print before selling.

When a design has parts that must fit, Claude also builds in a small **fit-test piece**: just the slot, hole or clip, from the same file. Plinth makes it on this Mac after each render (free; it doesn't use up Claude's renders) and checks it is one solid, sits flat, is much smaller than the part and reports the same fit sizes. Plinth checks its size, volume and reported sizes, not that its shape matches the part, so look at the **Fit Test** preview too. **Save Fit Test to Library** adds “Name (fit test)”; print it first (**Order a Sample to Me…** in Models can print it) and **Save Template…** as well. If the piece is tight or loose, change **Fit clearance** in **Personalise from Template…**, or tell Claude by how much (“the slot was 0.3 mm too tight”) while the window is open. Claude also compares each render with your photos when they show the accessory or an example of it, and otherwise checks where the design meets the object, such as cut-outs for ports; the result shows its comparison under **Compared with your photos**, beside Plinth's own checks.

**Not sure what to make?** In the same sheet, add your photos and press **Suggest Accessories** under **Ideas**. Claude says what it thinks the object is (with how confident it is, any text it can read on it and other things it might be) and suggests up to six accessories you could sell for it, each with what to make, the fit it needs (**Loose**, **Snug**, or **Tight**: measure with calipers and test a print first), any hardware, and the measurements to take with how to take them. If it guessed wrong, type or click what the object is in **What is it?** and press **Suggest Again**; **More Ideas** asks for different ones (up to 12; then **Suggest Again** replaces them, after asking). **Use This Idea** fills **What to make** and adds the measurement rows for you to type the sizes into (it asks first before replacing details you typed, and never discards a size you typed); nothing is designed until you press **Start Design**, which builds it as above. Each press is one request, never resent by itself, with its cost shown first (roughly $0.05–$0.35). Plinth leaves out any idea outside what it suggests, such as weapons, children’s products, protective gear, vehicle controls, food-contact and medical items, and removes claims such as “food-safe” or “sells well” from Claude’s text; it doesn’t suggest accessories at all for weapons, drug items or children’s products. Ideas stay only while the window is open, and survive **Start Over**, so you can design another without asking again.

**Generate a Replica from an Image…** (File menu or the Models **Import Model** menu) makes a printable model from photos with Meshy or Tripo. Add a **Front** photo and, for a more accurate back and sides, up to three more: **Left side (its left)**, **Back** and **Right side (its right)** — the object’s own sides, so its left is on your right when you face its front. Take each side photo a quarter turn from the front, straight on, at the same distance, with the same lighting and a plain background; step back and zoom in rather than shooting close up. One photo uses each service’s single-image generation and two to four its multi-view generation, at the same price. Then give a name, its real size along one side (**Height**, **Width**, **Depth** or **Longest side**, 5–220 mm) and a purpose: a **Display piece** keeps up to 200,000 triangles and a **Functional part** 20,000 (Plinth asks the service for more detail and simplifies on this Mac, showing how far simplifying moved the surface), with a warning that a model made from one photo isn’t dimensionally accurate, so a part that must fit something should use **Design an Accessory from a Photo…**. **Higher detail** (display pieces only, off each time) asks Meshy for its Ultra 2K geometry (+5 credits) or Tripo for detailed geometry (+20). The sheet shows the service, its approximate price beside the button (about 20 Meshy credits, or 25 Tripo credits including the conversion to STL, plus Higher detail) and **Check Balance** (free); if you change the photos, the service or Higher detail after pressing it, nothing is sent until you check the new price. **Generate Replica** sends the photos once and is never the default button. While it works, **Stop** takes effect only between status checks, never during a request that spends credits, and leaves the task running at the service, which may still charge for it; **Keep Waiting** or **Try Download Again** carries on with the same task without generating it again (for Tripo, a conversion to STL not yet sent is sent once, about 5 credits). If Plinth can’t tell whether the service received a request, it remembers that until you quit, and **Generate Again…** asks first (**Don’t Generate** is the default); closing with an unsaved model or a possible charge asks too. If the finished model is too large for Plinth to download or read (over 128 MB), the credits are spent, the model stays on the service’s dashboard (Meshy keeps it for 3 days), and generating again without Higher detail may help. On this Mac, Plinth scales the model to the size you typed (neither service knows the real size), repairs it, simplifies it if needed and checks it, then shows its size, triangles, mesh check, walls and overhangs. Answer **Which way is up?** (**As Made** or **Turned Upright**), then **Save to Library** adds “Name (replica)”. **Process Again** is free, and **Check Printability with Meshy** (Meshy only) asks Meshy, free of charge, to check its own model at your size. After saving, **Review for Printing with Claude…** opens once the sheet has closed.

**Review for Printing with Claude…** (the **Review for printing** card at the top of **Improve for printing**, STL only) first measures and renders the model on this Mac, sending nothing: its size and whether it fits the 220 mm build volume, the mesh check, wall thickness, flat contact with the bed, how much of the surface overhangs, and how that would change if the model were turned. Optionally say **What is it for?** and the **Real size**; without a size, Claude never suggests scaling. **Ask Claude** shows the estimated cost first (typically about $0.10–$0.60; the higher figure allows for the one follow-up Plinth sends if Claude doesn’t answer with a plan) and sends four pictures and the measurements, never the model file or its name; the pictures show any text on the model, such as a buyer’s name. Claude proposes a plan made only of Plinth’s own tools — repair, simplify, turn, scale to the real size, a flat base or a plinth, and Auto-improve (last, and not with a turn) — plus advice for you to follow, and advice about reinforcing offers **Open Reinforce**. Each step shows Plinth’s own figures beside Claude’s reason. Nothing is ticked: **Run Selected Steps** runs the steps you tick, in order, on a copy and saves one “Name (reviewed)”, provided it still passes the mesh check and fits the build volume wherever the original did; if a step can’t be done, nothing is saved. “Plinth’s checks found no problems” appears only when every check passes, including overhangs on under 2% of the surface.

Claude is an advisor: it never edits the model itself, only Plinth’s tools do, and its notes aren’t a strength rating or an approval. Costs shown before sending are estimates at list prices; your Anthropic, Meshy or Tripo bill is what counts. Requests to these services are never retried automatically: **Send Again** (Design an Accessory) and **Generate Again…** are explicit and billed again; the accessory designer shows the estimated cost of the next send beside its send buttons. Generate only objects you have the right to copy; trademarks, designs and other people’s work stay theirs, and checking a generated model’s licence and intellectual property is your responsibility. Nothing is uploaded to Slant until you choose **Upload Model** for a saved copy.

## Features

- Local model library with drag/drop, binary/ASCII STL, OBJ and 3MF preview (bounded size/triangle limits).
- Finder integration (packaged app): Plinth is listed in **Open With** for STL, OBJ and 3MF files, and accepts files dropped on its Dock icon. It registers as an alternate viewer, so it doesn’t take over your slicer’s default double-click. Opened files are copied into the library like any import; nothing is uploaded until you choose **Upload Model**. The window opens or comes forward when a file arrives. If a sheet, alert or dialog is open (such as a Pay or Cancel review) or a request is running, the import waits until it closes, so it never switches screens behind a review; a toolbar note shows how many files are waiting.
- Purpose-based preparation for brackets, clips, enclosures, decorative and custom parts. Automatically selects among six axis-aligned placements and up to 24 additional surface-normal directions using bed contact, overhangs, height and stress direction; saves a separate binary STL without scaling or reshaping. Purpose, source link, placement and selected material ID persist with the prepared copy. Custom descriptions are saved as context, not interpreted by an AI model. Existing libraries remain compatible. These are geometry heuristics, not mechanical simulation or a guarantee of strength or finished tolerances; production settings remain with Slant. OBJ and 3MF models need **Save STL copy** first; files over preview limits require external preparation.
- Presigned direct upload with stage reporting; cloud file list, metrics, estimates, materials/components/stationery browsers.
- Multi-item order drafts, Paste Address, saved products added to a draft by units sold with a fresh-estimate cost check, draft import from Etsy/Shopify/template CSV files or straight from a connected Shopify store (with optional per-buyer models from an OpenSCAD template), Pay Several Drafts (one review, paid one at a time), tracking sent back to Shopify, a spending report with printing cost per product and delivery per country, duplicate-as-new-draft reordering with visible copied item options, discard confirmation, large-quantity highlighting, advisory postcode format checks, date/amount sorting and CSV export of the orders list, explicit pay confirm with fresh cost preview, cancel with refund-aware copy, activity history.
- Full OpenAPI-backed Workbench (searchable catalog, empty-search state, ⌘Return to fetch/review, no Return on confirm-sheet sends, cross-sheet unknown-outcome lock for charge/cancel, numeric pay totals, metadata/query validation).
- Menus: **Go** lists the sidebar destinations (⌘1 Models, ⌘2 Orders, ⌘3 Catalog, plus API Workbench and Activity, without shortcuts, when developer tools are on); **File** has **New Order Draft…** (⌘N; **New 3DAPI Order…** while 3DAPI is the print service), **Import Model…** (⌘O), **Upload from URL…**, **Rename Model…** and **Export Model…** (⇧⌘E) for the selected local model, **Export Orders…** on Orders, **Import Orders…**, **Tracking for Your Shop…**, **Spending Report…** and **Saved Products…** (each opens its sheet only), and **Refresh** (⌘R); with 3DAPI chosen they follow its rules (see [Printing with 3DAPI](#printing-with-3dapi)). These are disabled and ignored while a sheet, alert or dialog is open in any window, including the Settings window, and no menu item uploads, places, pays for or cancels anything. If you close the main window, **Window › Plinth** (⌘0) or a click on the Dock icon brings it back, and File and Go commands reopen it first. **Help › Plinth Help** opens a short guide; with developer tools on, the Help menu also links to Slant’s API documentation.
- Session-only API-key management links to the dashboard; customer create/checkout not offered by the public API.
- Rate-limit-aware errors; no bearer credentials on storage URLs.
- A choice of print service: Slant 3D, or 3DAPI with an integrator key of your own. With either, **Get 3DAPI Quote…** sets 3DAPI's print and shipping price beside Slant's; with 3DAPI chosen, orders are composed on this Mac and placed only after a review and an explicit **Place Order**, never retried, with 3DAPI's order list, cancel, tracking, tools and order updates (see [Choosing a print service](#choosing-a-print-service)).
- 3MF designer and licence details with a selling advisory; drag models out of the library as temporary copies.
- On-Mac mesh tools (repair, simplify, scale to size, flat base, plinth, wall-thickness check) and optional design tools with your own keys: an accessory designed from photos by Claude and rendered with OpenSCAD, a replica generated from a photo by Meshy or Tripo, and a Claude review for printing that runs only the steps you tick.

Contributor guidance is in [AGENTS.md](AGENTS.md).

See [docs/API_REFERENCE.md](docs/API_REFERENCE.md) for the endpoint table (Guided / Workbench / Unavailable), doc-vs-spec conflicts, rate limits, and webhook HMAC verification, and [docs/3DAPI_REFERENCE.md](docs/3DAPI_REFERENCE.md) for 3DAPI quotes and orders.

## Data and security

- API key: Keychain service `Plinth` / account `api-key`.
- Shopify (optional): the client ID and secret, or access token, in Keychain service `Plinth` / account `shopify-credentials` (this Mac only); the store's myshopify.com address and the **Email customers their shipping details** choice in preferences. Shopify's access token is kept in memory only, and Plinth contacts only your store's myshopify.com address. Customer names, emails, addresses and sale amounts from **Fetch from Shopify** stay in the import sheet's memory like a CSV import's, and the names and postcodes compared by **Send Tracking to Shopify…** are never saved. **Disconnect…** deletes the Keychain item and the store address.
- Local models: `~/Library/Application Support/Plinth/` (files are stored under internal names; use **Export…** for a named copy). Removing a model moves its library copy to the macOS Trash, named after the model; empty the Trash to delete it permanently.
- Thumbnails: `~/Library/Application Support/Plinth/Thumbnails/<model id>.png`, rendered locally from the model file, regenerated when the library file changes and deleted when the model is removed. Mesh-check results are kept in memory only. Neither is sent to Slant.
- Optional delivery location: **Use Current Location**, at the top of an order draft’s **Deliver to** section, requests macOS permission only when pressed. Apple Location Services and reverse geocoding suggest an address for review; **Use This Address** fills the editable shipping fields, preserving name/email and clearing the old unit number. No background tracking or coordinate storage is used. Lookup stops when cancelled or the form closes. Coarse/stale fixes, permission denial and missing street addresses fall back to manual entry. The packaged app includes the required permission descriptions; command-line runs explain that the packaged app is required. Address mapping and location-quality checks have automated coverage. Live permission and address lookup still need a walkthrough on a Mac with Location Services available.
- Saved products: `~/Library/Application Support/Plinth/products.json`. They hold names, SKUs, quantities and Slant model/material/component/stationery IDs only — never prices, addresses, emails, order metadata or payment IDs. If the file can't be read, a copy is kept as `products.unreadable.json` before anything is saved over it.
- Preferences: UserDefaults, domain `io.github.tmm22.plinth` (including uploaded models you chose to hide from the library; hiding never deletes anything from Slant). Addresses and response bodies stay in-session memory.
- Slant Studio's data: after [moving from Slant Studio](#moving-from-slant-studio), its folder (`~/Library/Application Support/SlantStudio/`), Keychain items (service `SlantStudio`) and preferences (`app.slantstudio.mac`) stay on this Mac until you delete them; Plinth only reads them, apart from deleting a key's old copy when you remove or disconnect that key in Plinth, deleting the old copy of your saved address when you remove it, and working in Slant Studio's folder on a launch whose copy failed. Leftover `SlantStudio-…` temporary folders are cleaned up like Plinth's own.
- Order CSV export: **Export Orders…** writes only when you choose a file, and makes no network requests. Recipient names, emails, addresses and order metadata (which may hold your customer references) are left out unless you tick **Include recipient, address and metadata** in the save panel. Once saved, the file is outside Plinth’s control, so keep or delete it as you would any customer data. Cells that start with `=`, `+`, `-` or `@` are prefixed with an apostrophe so spreadsheet apps don’t run them as formulas. Activity records only how many orders were exported and whether those columns were included.

## Print-bed placement

Prepared copies sit at Z = 0 and use a flat contact face from the placements evaluated. Edge/point-only contact is excluded; contact area and width relative to height influence ranking alongside support and strength preferences. The preview shows an illustrative bed beneath the prepared model. No bottom flattening, cutting, scaling, brim or raft geometry is added. If none of the evaluated positions provides flat contact within the build volume, custom placement is needed externally. This is a geometric placement heuristic, not an adhesion or warping simulation.

The approach follows [Prusa’s FDM design guidance](https://help.prusa3d.com/article/modeling-with-3d-printing-in-mind_164135) on orientation and bed-facing surfaces, and [Slant’s production guidance](https://www.slantpod.com/post/what-is-slant-3d-s-print-quality) on minimising support and testing actual prints. [Prusa’s warping guidance](https://help.prusa3d.com/article/warping_2011) also makes clear that bed adhesion depends on material, temperature and machine preparation. A larger base alone does not guarantee production reliability. Numerical coplanarity tolerance and ranking weights are app heuristics, not provider specifications.

## Optional edge improvements

**Design improvements** appears under **Improve for printing** only when it can edit the model, or on a copy that already has an edge edit (where it summarises that edit). The check uses triangle normals, not recovery of CAD features, and is limited to 100,000 triangles; it does not claim to identify every fillet or infer mating surfaces. Other shapes don’t show the card: edit their edges in the source CAD model.

For exactly recognised closed, outward-wound, 12-triangle solid rectangular parts, **Review Edge Improvement…** offers a 45° bottom chamfer or rounded vertical corners, adjustable in size with a before/after preview. These edits remove material and retain the overall envelope, not the original edge shape or contact area. The user identifies whether the affected edges are non-critical before saving. Detailed, hollow, already treated, open or ambiguous models are never replaced by their bounding box. Generated files are parsed and checked before saving as a separate local model; originals and cloud files remain untouched. Prepared load directions are remapped to the edited model’s axes, and new copies require a new upload and estimate.

The treatment choices follow [Prusa’s fillet/chamfer guidance](https://help.prusa3d.com/article/modeling-with-3d-printing-in-mind_164135) and [Autodesk’s additive design considerations](https://www.autodesk.com/learn/ondemand/curated/design-for-additive-manufacturing-with-fusion/5p0AhR0t0k8663u0OScBmt). External corner rounding is not presented as structural reinforcement; internal load-bearing fillets require the original CAD model and load context.

### Expanded placement and material matching

The placement search groups triangle normals by direction and evaluates the largest groups first, with a maximum of 30 candidates. Every candidate is checked against the whole mesh for actual bed contact and build volume. This is a bounded search, not a global orientation optimum; it does not search in-plane rotations or simulate support removal. Rotations preserve triangle geometry within floating-point precision. Existing six-position recipes remain readable. Oblique load directions are not rounded to an axis when creating an edge-edited copy; the user chooses a new direction when needed.

**Material suggestions for this use**, a small disclosure under the placement in **Optimise for purpose**, offers optional rigidity (PLA), toughness and occasional flex (PETG), and outdoors, sun or warmth (OPM, Slant's outdoor material, then PETG away from a car dashboard or glass) guidance. Until you choose a requirement it follows the saved purpose: decorative parts and enclosures PLA, brackets and clips PETG, custom parts none. When a selected STL has a saved purpose and its material differs from the suggestion, a one-line hint beside the Material picker in Print configuration offers **Use PETG** (or the suggested material) and **Keep Current Material**, which hides it for that model; the PLA hint shows only while no material is chosen, and the hint never shows on a prepared copy. Nothing is suggested for parts that touch food. It uses exact catalogue profiles with confirmed availability and changes the material in Print configuration only when the user picks a suggestion. Unknown blends receive no inferred rating. Repeated flexing and warm environments require supplier performance data and application testing; the app does not invent fatigue or temperature ratings. The requirement is saved with the part and prepared recipe. Guidance follows [Prusa’s PLA guide](https://help.prusa3d.com/article/pla_2062) and [PETG guide](https://help.prusa3d.com/article/petg_2059); these describe material families, not Slant-specific performance certification.

### Prepare new models for printing

Slant prints every part with the same fixed settings, which no order or API call can change (published on Slant's blog): 0.2 mm layers (0.3 mm first layer), 1 mm walls (about two lines), 25% infill, overhangs up to 50°, no brims, a 0.4 mm nozzle and a 220 mm cube. It keeps the orientation you upload unless it is obviously wrong, so the way a model sits in Plinth is the way it prints. Slant recommends parts at least about 20 mm across (Plinth shows this as advice) and charges for each separate body after the first (about $0.39 each in a test on 25 Oct 2026); the mesh check counts bodies, a closed hidden pocket counts as one, and the estimate names the charge (“Charge for N extra bodies”).

**Prepare new models for printing** (Settings › Design Tools, on by default) makes a separate “Name (print-ready)” copy on this Mac when you import an STL, open one from Finder, drag one in, save an STL copy of an OBJ or 3MF, or save a replica. It never changes or replaces the original, never selects the copy for you and never uploads anything: the original shows **Print-ready copy saved · Show Copy**, and the upload area says when a print-ready copy exists. The copy:

1. is repaired if the mesh check found problems (if repair can't make it sound, no copy is made and Plinth points you to **Repair and simplify**);
2. is placed for printing, using the part's purpose when it is set: at least 100 mm² (or 15% of the footprint) flat on the bed, a centre of mass well inside that contact, then the fewest overhangs. It is then turned about Z so faces drawn at an angle line up with the printer's axes (replicas, decorative parts and already-placed models keep their placement);
3. gets only changes that don't move a fitting surface: bridging layers in counterbore ceilings, and chamfers under free ledges at 45°, or up to Slant's 50° where there is less room below (check any ledge something hooks or slides under);
4. gets a **0.4 mm bottom-edge chamfer** round its outer bottom edge, so the 0.3 mm first layer's spread stays inside the outline. Hole entries keep their size. It is skipped when there is no flat bed face, the sides slope or are already chamfered near the bed, the part is under 5 mm across, the bottom face has a shallow recess or step, a hole is within 0.8 mm of the edge, or it would take over 40% of the bed contact. Because most parts have a flat bottom edge, almost every new STL gets a print-ready copy while this is on;
5. gets **internal walls** (see Reinforcement copies) following its saved purpose: a thin ring-shaped gap about 1.5 mm out from each round hole that opens through the base (the hole itself is unchanged), one slot through the middle of upright pins and bosses 3–8 mm across, and one slot along straight sections 2.5–5 mm thick, each keeping at least 1 mm of material all round. Slots through thick regions are added only for a saved purpose other than Decorative (Enclosure and Custom included); decorative parts get none. A saved stress direction sets their direction. Every gap opens through the base, so the part stays one body.

The copy says each step in one sentence, with Plinth's figures under **Details**: overhangs steeper than 45° and past Slant's 50°, how far it was turned, the internal walls by kind and Plinth's estimate of the extra filament (from Slant's 1 mm walls and 25% infill), areas thinner than 1 mm, and up to 8 print checks. The checks are slender upright features on parts saved as a bracket, clip or custom part (layers run across them, so they are likely weaker standing than lying flat), pins under 3 mm, holes within 1.5 diameters of an edge (centre to edge), large sharp-cornered footprints at least 60 mm each way (they can lift, since Slant uses no brims), a small bed contact and a tipping risk; each says what to do. Internal walls likely raise Slant's price: estimate both models before choosing. Slender upright features point to **Lay It Flat Along Its Length…**. If the part has round holes running sideways, the copy offers **Add Teardrop Holes…**: tick the holes whose upper sides don't have to fit anything (none are ticked to start, and Cancel is the default). Plinth makes a new “Name (print-ready, teardrop holes)” copy from the original, placed the same way, where each ticked hole gets 45° upper sides up to a flat top at the hole's own top, so its bottom and height are unchanged but anything fitting its upper sides will be looser; the bottom chamfer and internal walls follow round the new shapes. Slant may still put support inside a hole. A teardrop run that saves nothing reports on the copy and leaves the original's status as it was. **Add Fillets and Thicken Walls…** on the copy adds inside-corner fillets and thicker walls (to whole 0.5 mm lines; Slant's 1 mm wall is about two) as a further copy, only if nothing on the part has to fit; the two sit together, and if you want both, add teardrop holes first. Personalised models, designed accessories and fit-test pieces, copies made by Plinth's tools or from a print-ready copy, models whose licence forbids derivatives, OBJ and 3MF files, and models under 3 mm across (scale them first) aren't prepared automatically. **Make Print-Ready Copy** (a model's More menu or right-click) prepares any STL on demand, for example after you set its purpose in **Optimise for purpose** or scale it to the size you sell; the chamfer and internal-walls switches apply to it too, even with automatic copies off. A preparation that runs out of time (internal walls stop after 120 s) saves nothing: for very detailed parts, turn off **Add internal walls** or simplify a copy first.

**Hidden pockets.** A closed cavity sealed inside a part counts as a separate body, and Slant charges for each body after the first (about $0.39 each in a test on 25 Oct 2026). The inspector reports hidden pockets on any STL with their total extra cost, the material filling would add and any loose parts inside, which filling removes. **Fill Hidden Pockets** (inspector, the print-ready copy's panel, or the More menu once pockets are found) saves a separate “Name (pockets filled)” copy; it checks every corner of each pocket against the part around it and refuses if any is uncertain. Separate parts are left alone, and Plinth never fills pockets by itself. A model with very many separate parts may be too big to check.

### Reinforcement copies

**Reinforce this part** is a collapsed optional panel for closed, consistently oriented STL meshes up to 20,000 triangles. It supports internal ribs, triangular gussets, additive inside-junction fillets, mounting collars, overhang support chamfers, wall matching to line width, teardrop hole roofs, counterbore bridging layers, splitting with alignment pins, and three experimental treatments (internal shell gap, hole-wall ring gap, four-cell internal cavities). Operations use Euclid 0.10.0 (MIT, pinned in `Package.resolved`); the licence ships in the app bundle. Features are fused/subtracted as solids rather than exported as overlapping shells.

Choose a treatment, local dimensions, axis direction and a position measured from the model minimum. **Suggest Position** tries a bounded 27-position search for a geometric starting point. It is not a stress analysis or a complete search, and it does not infer the space needed by electronics or mating parts. **Update Preview** validates the candidate; the user reviews the placement before applying. Keep-clear boxes reject changes to protected regions, and a side-by-side cutaway shows internal changes without cutting the exported part. Suggestions may still need manual placement or CAD work, particularly for off-axis bores and complex joints.

Additive features must overlap existing material, make a measurable change, stay within the original overall envelope and avoid introducing a disconnected body. Mounting collars require a clear nominated bore and a complete annular seat at one end; they never drill an opening. The nominated clearance and protected regions need to include all required counterbores, fastener access and assembly clearance. Inside fillets add material, unlike the existing external-corner rounding tool. Another reinforcement can be added to the resulting copy, with each source version retained; on curved geometry, a repeatedly regenerated copy may instead report that a CAD edit is needed.

Before any solid operation, imported STL triangles are grouped into flat faces and each vertex is moved (by well under 0.1 µm) onto its face planes, with needle-shaped triangles merged into neighbouring polygons. Float STL rounding otherwise leaves faces slightly non-coplanar, which Euclid's Boolean operations turn into open seams around round holes. If a mesh cannot be cleaned this way, the original triangles are used and the exported-copy checks still apply. On export, a thin triangle that rounds to three collinear Float points is replaced by an edge flip with its neighbour rather than dropped, so the seam stays closed.

Print-process treatments depend on the layers, so they stay Z up (use **Turn about Z** to point them) and lock the saved copy's print orientation to Z up:

- **Overhang support chamfer** fills under a ledge with a 45° wedge so it prints without supports.
- **Match wall to line width** measures the wall through the region centre along local Y and thickens its +Y side to a whole number of extrusion lines. The line width (default 0.45 mm) is an estimate, because Slant does not publish its toolpath width.
- **Teardrop hole roof**: **Find Horizontal Holes** lists round holes 3–30 mm across whose axis is within 5° of horizontal; tick the ones whose upper sides don't have to fit anything (none are ticked). Each gets 45° upper sides up to a flat top at the hole's own top, so its bottom and height are unchanged; holes that are too small, tilted, stepped, crowded or have under 1 mm of material above are listed with the reason. A pointed roof along local X can still be placed by hand. On a print-ready copy, or a copy made from one, Reinforce points to **Add Teardrop Holes…** in the copy's panel, which rebuilds the chamfer and walls round the new shapes, or says why it isn't available.
- **Counterbore bridging layers** cut a one-layer strip, then a one-layer square, into a downward-facing counterbore ceiling, so each layer bridges between solid edges. Set position Z at the ceiling and the layer height to match the print. This slightly reduces the screw-head bearing area.
- **Internal walls** cuts thin (0.25 mm) slots up from the bottom face into solid regions at least 5 mm thick, 4 mm apart and at least 2 mm from every other surface, so Slant's printer adds walls round each one. The part stays one body; the outside and every fit surface are unchanged. It uses more filament, so get a new estimate (one Slant estimate on 25 Oct 2026, for a 40 × 40 × 20 mm block, rose about 27%).
- **Hole-wall ring gap** (experimental) cuts a thin gap around an existing vertical bore, open through the bottom face, so the slicer prints extra perimeters on both sides. A slicer may merge a gap that is too narrow for its toolpaths.
- **Internal shell gap** and **Internal cells** are withdrawn: they left closed hidden pockets, and Slant charges for each one as a separate body. Older copies made with them still open. Reinforce refuses any copy with more separate bodies than the original.

**Split with alignment pins** cuts the part on the region's local mid-height plane and drills matching blind pin holes in both halves. It saves two part copies, each of which can then be prepared in its own orientation. The joint is weaker than solid material, so keep it away from peak loads.

Bridging, ring gap, wall matching, split and the hand-placed teardrop roof are placed manually; **Suggest position** is not offered for them.

Internal walls and the ring gap don't override Slant's wall count or guarantee more strength. Experimental copies require an explicit test-print acknowledgement. There is no automatic “approved” status or inferred strength percentage. All treatments require verification on representative prints before treating them as production-qualified.

Geometry checks cover closed directed edges, winding, envelope, connected-body count, serialized volume and protected-region changes. They do not prove absence of every self-intersection or guarantee finished tolerances, structural performance, adhesion or Slant’s toolpaths. Preview work runs off the main thread, has cooperative cancellation and a time limit, and invalidates on setting changes. Results are saved as separate local STL files with treatment/region metadata, preserving the source; a new upload and quote are required. The displayed geometric volume change is not a filament-use or price estimate. The 1.2 mm feature floor is an app heuristic, not a provider manufacturing specification.

### Auto-improve

**Auto-Improve & Save Copy**, in **Auto-improve** under **Improve for printing**, applies every treatment that the app can place reliably in one click and saves the result as a single new local copy. It uses the purpose set in **Optimise for purpose**; until a bracket, clip or custom part has a stress direction (and a custom part a description), the card’s summary says what to set first. There is no review step before saving, so check the saved copy's summary and preview before uploading it. **Return to Original** goes back to the untouched source.

It first chooses a print orientation for the part's purpose. Prepared copies and copies that are already locked to Z up keep their orientation. It then re-detects features on the current geometry and applies them in this order:

1. **Counterbore bridging layers** in downward-facing counterbore ceilings with two concentric round edges (0.2 mm layers).
2. **Overhang support chamfers** under downward-facing ledges up to 15 mm deep. Deeper ledges, and ledges without enough height below them, are reported for manual work.
3. **Wall matching** for inner walls 0.65–2.7 mm thick, which are thickened inward only to a whole number of 0.45 mm lines. Outer surfaces and the overall envelope are not changed.
4. **Inside-junction fillets** on up to 12 concave edges, longest first, sized from the thinner adjoining wall (1.2–3 mm). Decorative parts receive no fillets.

The copy keeps the orientation it was improved in, because these treatments depend on the layers. Every step goes through the same checks as a manual reinforcement, plus a volume-conservation check. If a step fails, it tries an alternative placement and is otherwise skipped, with the reason listed under **Skipped after checks**. The run stops after four minutes, and **Stop** discards the work without saving.

Teardrop roofs, mounting collars and edge chamfers or rounding change fit-critical or visible surfaces. They are therefore listed under **For your review** and never applied automatically. Ribs, gussets, splitting and the experimental treatments are also never automatic. Detection only recognises axis-aligned flat faces and round edges, so angled or freeform features are not treated. The 0.45 mm line width and 0.2 mm layer height are estimates, not Slant specifications. Test-print the copy before relying on it.
