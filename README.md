# Slant Studio for Mac

A native SwiftUI macOS client for the [Slant 3D V2 API](https://slant3dapi.com/documentation/introduction). Import an STL, OBJ or 3MF model (from the Import panel, drag and drop, or Finder’s **Open With**), preview geometry, upload to your platform, estimate cost, draft an order, and submit for production—with an API Workbench covering every documented operation.

## Run

Requires macOS 14+ and Xcode 16+ / Swift 6. Euclid 0.10.0 is pinned for solid geometry operations; its licence ships with the app.

```sh
swift test
./scripts/build-app.sh
open "dist/Slant Studio.app"
```

Or open `Package.swift` in Xcode / `swift run SlantStudio`. Packaging is ad-hoc signed for the current Mac; public distribution needs Developer ID signing and notarization.

## Connect and print

1. **Connection** — save your API key to Keychain and test; load or create a platform (billing is configured in Slant’s dashboard).
2. **Models** — import/drop an STL, OBJ or 3MF for local preview. Uploads send the file in its original format. With no model selected, Models shows a single prompt with **Import Model…** (and **Connect Slant Account…**, which opens Settings, while no API key is saved). The optional geometry tools are grouped under **Improve for printing**, all collapsed, in the order they are usually used: **Optimise for purpose**, **Auto-improve**, **Reinforce this part**, and **Design improvements** when it can edit the model. In **Optimise for purpose**, choose the part’s use and stress direction where needed, then **Optimise & Save Copy**. The app remembers the purpose and prepares a rotated STL with its geometry and dimensions preserved. **Upload Model** runs presigned upload + confirm. Estimate the prepared copy with material and quantity.
   The next action stays in a fixed bar while you scroll: **Upload Model → Get Estimate → New Order Draft…**. Without a platform, the bar offers **Create Platform…** when the account has none, or **Choose Platform…** (in Settings) when it has some. Material and quantity are in **Print configuration**, below the preview and mesh check and above the optional geometry tools; the **Material** menu lists every material grouped by type, with out-of-stock ones labelled. Missing materials and invalid quantities link back to the configuration; previous estimates are labelled when settings change. **Upload Again…** in the **…** (More) menu asks for confirmation, because it creates a second file in Slant rather than replacing the first. A prepared copy whose saved material differs from the current selection offers **Use Prepared Material** under the material picker; the selection never changes on its own.
   **Compare estimates…** appears under the quantity once the model is uploaded and materials are loaded. It prices up to 4 in-stock materials (grouped by type) at up to 5 quantities side by side — by default the current material at 1, 5, 10, 25 and 50 — sending at most 20 estimate requests one at a time, only after you press **Get estimates**; **Stop** or closing the sheet cancels the rest, and nothing is retried automatically. Each cell shows the print-cost total and the price each (total ÷ quantity, including any surcharges), with the lowest per unit marked in each column; delivery is priced later, in the order draft. **Use** sets that material and quantity in Print configuration and keeps the estimate as the current one. Pacing and rate-limit stops are described in [docs/API_REFERENCE.md](docs/API_REFERENCE.md).
   The **…** (More) menu beside the model’s name holds the same items as the model’s context menu in the library, with destructive ones last: for a local model **Rename…**, **Export…**, **Save as Product…**, **Upload Again…** (once uploaded) and **Remove from Library…**; for an uploaded model **Show Local Copy** (when linked), **Copy ID**, **Hide from List** or **Show in List**, and **Delete from Slant…**, which asks first. Renaming changes the library name and later upload names; Slant cannot rename a file that is already uploaded. **Export…** saves a copy (for a slicer or CAD tool) under the model's name; the library file is never moved. Uploaded models that are also in the library show **On this Mac** and offer **Show Local Copy** before downloading another copy.
   **Upload from URL…** (the Import Model menu in the toolbar, or the File menu) asks Slant to fetch a model from an https link straight into your Slant account, on your current platform; it isn’t added to the library on this Mac.
   STL and OBJ files carry no units. If a model's largest dimension is under 3 mm, a notice suggests it may have been exported in inches, centimetres or metres; models larger than the 220 mm build volume are flagged on the preview instead. For a plain import, **Save Scaled Copy** offers only factors whose result fits the build volume (for example ×25.4 for inches). The copy is a binary STL, parsed and checked before it is added; the original is unchanged. Prepared or edited copies are not rescaled.
   OBJ and 3MF files get the same preview, dimensions and build-volume check as STL, and upload unchanged. OBJ polygons, including concave ones, are split into triangles on their own plane; textures, normals and materials are ignored. 3MF previews apply the file’s unit and every object placement, and ignore colours, paint data and plate settings; when a file places several objects, a note says the whole file is uploaded, so check the estimate covers them all. The **Improve for printing** tools work on STL, so an OBJ or 3MF model shows only a notice with **Save STL Copy**, which adds a separate STL copy (several objects become one mesh) and leaves the original untouched. An OBJ face that crosses itself can’t be converted exactly, so that file offers no STL or scaled copy. Size limits are listed in [docs/API_REFERENCE.md](docs/API_REFERENCE.md).
   Under the preview, a one-line **mesh check** of the model's surface (STL, OBJ or 3MF) reads “Mesh check: Closed, 1 part” when it is watertight, or gives the number of notes. Notes about open edges (gaps), edges shared by more than two faces, flipped or inward-facing faces, separate parts and zero-area triangles, with what each may mean for printing, are in a collapsed disclosure. Zero-area triangles alone don’t count against a model, and a 3MF whose objects are one part each is reported as “one per object”. It welds identical coordinates, runs in the background up to the 500,000-triangle preview limit, and is cached per file version for the session. It is advisory and never blocks upload; fix reported problems in your CAD tool or a mesh repair tool. Library rows show a small rendered thumbnail of each STL, OBJ or 3MF model, falling back to the cube icon while it renders or when a file can’t be read.
   **Remove from Library…** moves the library's copy of the model to the Trash under the model's name and removes the entry; **Edit › Undo** restores both during the same session, as long as the file is still in the Trash. Finder’s **Put Back** returns the file to a `Removed` folder inside Slant Studio’s support folder, not to the library: use **Edit › Undo** in the same session, or import the file again. Uploaded files in your Slant account are never deleted by this.
   For uploaded models, **Model analysis** shows Slant's production notes for the file when its team has added any, along with the reported metrics (including whether the part needs supports and the support volume estimate) and the upload and update dates when Slant provides them.
3. **Orders** — draft with delivery details and line items. The initial shipping country follows your Mac’s Region setting and stays editable; delivery details reused in the current session take priority. If the region cannot identify a country, choose one explicitly. The country menu lists common shipping countries first, then every other country, named in your Mac’s language; it comes first in the address because it decides whether a state is required and how the postal code is checked. When a new draft reuses this session’s last address, it says so (“Same address as your last draft: Ada Lovelace, London”) with **Edit** and **Clear**. **Advanced** under More options holds the shipping provider, a payment service ID and **Reference fields (metadata)**; it opens by itself when a duplicated order copied a shipping provider. The Owner ID sent with drafts is set in Connection › Advanced identifiers. **Review & Place Order…** charges and starts fulfillment. Cancel requests follow Slant’s cancel/refund rules.
   To reorder, choose **Duplicate as New Draft…** in an order’s details or the orders list’s context menu. Studio reloads the order and opens a new draft with its items, materials, quantities, delivery details, platform and shipping provider for you to check. Items without a model, component or stationery ID are listed as not copied, as is a quantity that isn’t a whole number (set to 1 for you to check). An address country Studio can’t recognise is left for you to choose, and if the order’s platform is no longer in your platform list, the draft says it uses your current platform. Old prices are never reused: Slant prices the new draft when you create it, and placing it uses the usual charge review. Duplicating is unavailable while that order’s last payment/cancel outcome is unknown.
   Item options copied from the original order (for example slicer options) are listed under each item as **Copied options — sent with this item**; **Remove Options** sends that item without them.
   For the US, Canada, the UK, Ireland, Australia, New Zealand, Germany, France, the Netherlands and Japan, a postal code that doesn’t match the usual format shows a warning under the field once you leave it, or while typing once it is long enough to judge. It never blocks the draft, and other countries get no check.
   The **Status** menu in the Orders toolbar reloads the list with that status straight away; **Filters** holds the date range and Newest/Oldest (the only way to start from your oldest orders). The list starts in the Newest/Oldest order chosen there; clicking **Created** or **Total** sorts the loaded orders by date or amount. Typing in the search box filters the loaded orders; Return searches all your orders on Slant, and clearing the box returns to the list. A note under the list says which you’re seeing. In an order’s details, **Cancel…**, **Duplicate as New Draft…** and **Review & Place Order…** sit directly under the header (a cancelled order shows why it can’t be cancelled instead). Orders being made or shipped show **Tracking** above the costs; drafts and cancelled orders don’t, unless Slant returned tracking details. Order details also show when the order was processed, the shipping provider and any delivery instructions, when Slant returns them, and each item’s own status when the items’ statuses differ. **File › Export Orders…** (on Orders) saves the orders currently in the list (after search and filters) as a CSV file: order number, created, status, items, costs, total, currency, carrier and tracking numbers. Columns Slant didn’t return for an order are left blank. Only loaded orders are exported; when Slant has older ones, the save panel says so.
   **Saved Products…** in the Orders toolbar keeps products you sell often: a name, an optional SKU (unique, ignoring case) and their items — library models with a material, components and stationery, each with a quantity per unit sold or **Once per order** (the default for stationery, such as a packing slip). **Save as Product…** in a library model's **More actions** starts one from that model and its prepared material, if it has one. In a draft, **Add Saved Product…** adds a product's items for the number of units sold (2 units of a product with 3 prints adds 6) after any items already there; it shows exactly what it will add, such as “Adds 6 × Bracket, 1 × Packing slip”, and Return adds it. A product can be saved before its model is uploaded, but it can't be added to a draft until the model is uploaded, its material is in stock and every item is still offered; Studio says what to fix. A model uploaded again is used in its latest upload. The SKU is sent with each item, and is how **Import Orders…** matches a marketplace order's items to the product.
   If **Create Draft** times out, loses its connection or gets a server error, Slant may have created the draft anyway. The draft form then names that attempt’s recipient and time — “Your Create Draft for Ada Lovelace at 2:32 PM didn’t get a reply from Slant, so that draft may exist. Check your drafts (Orders toolbar › Status › Draft) before creating it again.” — and the next **Create Draft** — in this form or a new one, for the rest of the session — asks you to confirm with **Create Anyway** (**Don’t Create** is the default). If several attempts went unconfirmed, the notice lists each one. The recipient names and times are kept in memory only and cleared when you change account. The notice clears only once a draft is created successfully; a definite refusal from Slant doesn’t clear it, because it says nothing about the earlier attempt. Draft creation is never retried automatically, and the error alert offers no **Try again** for it.
   Order details show the marketplace order number with a Copy button when the order’s metadata has `sourceOrderId` (and `source`: “Etsy order”, “Shopify order”, or “Imported order” for Studio’s template), if Slant returns metadata. The orders list shows it under the recipient, such as “Etsy order 3141592653”, and searching the list matches it.
   **Profit check** (collapsed under an order’s costs) estimates what you made on that order: enter what the buyer paid for the items and shipping, in US dollars, and choose marketplace fees — None, Etsy (US), Shopify Payments (US Basic) or Custom. It subtracts the fees and the order’s real Slant total (print + delivery) and shows each line, the estimated profit and the estimated margin. Etsy and Custom fees also ask for **Units sold** (default 1): the listing fee is charged per unit the buyer bought, which isn’t the number of items in the Slant order (a unit can need several prints and a packing slip). The preset rates are assumptions checked in October 2026 (Etsy: 6.5% transaction fee and 3% + $0.25 payment processing on item + shipping, $0.20 listing renewal per unit sold, optional 15% Offsite Ads capped at $100; Shopify Payments Basic: 2.9% + $0.30). The rates in use are shown as one dated line, such as “Etsy (US): 6.5% + 3% + $0.25 + $0.20/unit · checked October 2026” (“your rates” once edited); **Edit Rates** opens every rate for editing, so check them against your own account. If you sold in another currency, convert to USD yourself. Not included: taxes, refunds, ads you pay for separately and currency conversion. Without a usable Slant total (or for cancelled orders) it explains why instead of showing a number. Only the fee preset and rates are remembered; what the buyer paid and the units sold are never saved.
   **Import Orders…** (Orders toolbar or File menu) turns a marketplace CSV into order **drafts** for you to review: Etsy’s “Sold Order Items” download, a Shopify orders export, or Studio’s own template (**Save Template…** writes the columns with one example row). Comma, semicolon and tab files are recognised, including Excel’s `sep=;` first line. Each line’s SKU must match a saved product, which supplies the items, material and quantities; matching ignores case and surrounding spaces. Rows of one order with the same product are added together, so each product is expanded once for its total units (at most 10,000), and a once-per-order item that several of the order’s products share — the same packing slip, say — is added once. Items with an unknown SKU, or no SKU (then they’re listed by item name), appear once each under **Match products**, with a one-line list of the unknown SKUs and **Copy** so you can set them up in Saved Products. For each you can choose a saved product, or **Leave out of drafts** (for things like Shopify shipping protection); the choice applies to every order with that SKU or name, is never guessed, and lasts only until you choose another file or close the sheet — it isn’t saved. The preview lists one row per order with its recipient, country, the items its draft will contain (including stationery) and any problems. Orders that can’t be imported (an unknown SKU you haven’t matched, missing address fields, an unrecognised country, a missing state for the US, Canada or Australia, a quantity that isn’t a whole number, rows of the same order with different delivery details) can’t be ticked. Orders that need a second look start unticked: already shipped, cancelled or refunded on the marketplace, a Shopify shipping company (Slant drafts have no company field), a US ZIP with fewer than five digits (choose the zero-padded ZIP for that order if a spreadsheet dropped its leading zero; Studio never pads on its own), or one that looks already imported. Etsy files have no buyer emails, so orders without one need **Email for orders without one** (for example your shop’s); Studio never invents one. **Create N Drafts…** asks for confirmation (Return cancels it), then creates drafts one at a time, at most one a second, waiting for Slant’s rate limit when needed. Nothing is charged: each imported draft is then reviewed and paid one at a time through the existing charge review in Orders. A draft Slant refuses is reported and the rest continue; if Slant doesn’t confirm one (a timeout, connection loss or server error), the import stops at once and marks it as possibly created — check your drafts before importing it again. Requests are never retried. **Stop**, or closing the sheet, takes effect before the next request. Afterwards the orders list reloads showing drafts (the toolbar’s **Status** menu set to Draft), and **Show Drafts** closes the sheet to show them. Each draft’s metadata records `source` and `sourceOrderId`, and orders already imported this session, or found in loaded orders’ metadata, start unticked; older orders that aren’t loaded aren’t checked, and the sheet says so.
   Cancel or Escape closes an untouched draft immediately; once you’ve changed items, delivery details, platform or shipping provider, or typed reference fields (metadata) or a payment ID, Studio asks before discarding them. A quantity of 25 or more shows a “check for an extra zero” note under the Models quantity field and in the draft, and is highlighted in the charge review; it doesn’t block the order.
4. **API Workbench** — every catalog operation against production, with parameter validation, JSON bodies, mutation review, typed confirms for high-risk deletes/secret rotation, and secret redaction in responses.

Live traffic uses the **production** API. Mutations are never auto-retried. If a network error leaves a charge or cancel outcome uncertain, Studio locks that order across Orders and the Workbench until you reload it and the result is clear. If the status still hasn’t changed, check the order in your Slant dashboard; the lock lasts for the session. A definite refusal from Slant (an HTTP 4xx other than 408/409, such as a declined payment) means nothing is pending, so the order stays unlocked.

## Features

- Local model library with drag/drop, binary/ASCII STL, OBJ and 3MF preview (bounded size/triangle limits).
- Finder integration (packaged app): Slant Studio is listed in **Open With** for STL, OBJ and 3MF files, and accepts files dropped on its Dock icon. It registers as an alternate viewer, so it doesn’t take over your slicer’s default double-click. Opened files are copied into the library like any import; nothing is uploaded until you choose **Upload Model**. The window opens or comes forward when a file arrives. If a sheet, alert or dialog is open (such as a Pay or Cancel review) or a request is running, the import waits until it closes, so it never switches screens behind a review; a toolbar note shows how many files are waiting.
- Purpose-based preparation for brackets, clips, enclosures, decorative and custom parts. Automatically selects among six axis-aligned placements and up to 24 additional surface-normal directions using bed contact, overhangs, height and stress direction; saves a separate binary STL without scaling or reshaping. Purpose, source link, placement and selected material ID persist with the prepared copy. Custom descriptions are saved as context, not interpreted by an AI model. Existing libraries remain compatible. These are geometry heuristics, not mechanical simulation or a guarantee of strength or finished tolerances; production settings remain with Slant. OBJ and 3MF models need **Save STL copy** first; files over preview limits require external preparation.
- Presigned direct upload with stage reporting; cloud file list, metrics, estimates, materials/components/stationery browsers.
- Multi-item order drafts, saved products added to a draft by units sold, draft import from Etsy/Shopify/template CSV files, duplicate-as-new-draft reordering with visible copied item options, discard confirmation, large-quantity highlighting, advisory postcode format checks, date/amount sorting and CSV export of the orders list, explicit pay confirm with fresh cost preview, cancel with refund-aware copy, activity history.
- Full OpenAPI-backed Workbench (searchable catalog, empty-search state, ⌘Return to fetch/review, no Return on confirm-sheet sends, cross-sheet unknown-outcome lock for charge/cancel, numeric pay totals, metadata/query validation).
- Menus: **Go** lists every destination (⌘1 Models, ⌘2 Orders, ⌘3 Catalog, ⌘4 Connection); **File** has **New Order Draft…** (⌘N), **Import Model…** (⌘O), **Upload from URL…**, **Rename Model…** and **Export Model…** (⇧⌘E) for the selected local model, **Export Orders…** on Orders, **Import Orders…** and **Saved Products…** (each opens its sheet only), and **Refresh** (⌘R). These are disabled and ignored while a sheet, alert or dialog is open, and no menu item uploads, places, pays for or cancels anything.
- Session-only API-key management links to the dashboard; customer create/checkout not offered by the public API.
- Rate-limit-aware errors; no bearer credentials on storage URLs.

Contributor guidance is in [AGENTS.md](AGENTS.md).

See [docs/API_REFERENCE.md](docs/API_REFERENCE.md) for the endpoint table (Guided / Workbench / Unavailable), doc-vs-spec conflicts, rate limits, and webhook HMAC verification.

## Data and security

- API key: Keychain service `SlantStudio` / account `api-key`.
- Local models: `~/Library/Application Support/SlantStudio/` (files are stored under internal names; use **Export…** for a named copy). Removing a model moves its library copy to the macOS Trash, named after the model; empty the Trash to delete it permanently.
- Thumbnails: `~/Library/Application Support/SlantStudio/Thumbnails/<model id>.png`, rendered locally from the model file, regenerated when the library file changes and deleted when the model is removed. Mesh-check results are kept in memory only. Neither is sent to Slant.
- Optional delivery location: **Use Current Location**, at the top of an order draft’s **Deliver to** section, requests macOS permission only when pressed. Apple Location Services and reverse geocoding suggest an address for review; **Use This Address** fills the editable shipping fields, preserving name/email and clearing the old unit number. No background tracking or coordinate storage is used. Lookup stops when cancelled or the form closes. Coarse/stale fixes, permission denial and missing street addresses fall back to manual entry. The packaged app includes the required permission descriptions; command-line runs explain that the packaged app is required. Address mapping and location-quality checks have automated coverage. Live permission and address lookup still need a walkthrough on a Mac with Location Services available.
- Saved products: `~/Library/Application Support/SlantStudio/products.json`. They hold names, SKUs, quantities and Slant model/material/component/stationery IDs only — never prices, addresses, emails, order metadata or payment IDs. If the file can't be read, a copy is kept as `products.unreadable.json` before anything is saved over it.
- Preferences: UserDefaults (including uploaded models you chose to hide from the library; hiding never deletes anything from Slant). Addresses and response bodies stay in-session memory.
- Order CSV export: **Export Orders…** writes only when you choose a file, and makes no network requests. Recipient names, emails, addresses and order metadata (which may hold your customer references) are left out unless you tick **Include recipient, address and metadata** in the save panel. Once saved, the file is outside Studio’s control, so keep or delete it as you would any customer data. Cells that start with `=`, `+`, `-` or `@` are prefixed with an apostrophe so spreadsheet apps don’t run them as formulas. Activity records only how many orders were exported and whether those columns were included.
- Order CSV import: **Import Orders…** reads the file you choose into memory only. Imported names, emails and addresses stay in the import sheet for as long as it is open and are sent to Slant only in the drafts you confirm; they are never written to disk, preferences, logs or Activity, and closing the sheet discards them. The list of source order IDs imported this session (used to flag duplicates) is kept in memory and cleared when you quit or change account. Activity records only how many drafts were created, refused, not confirmed or not sent.
- API: `https://slant3dapi.com/v2/api` (+ documented `/v2/slant/webhook` exception).

## Print-bed placement

Prepared copies sit at Z = 0 and use a flat contact face from the placements evaluated. Edge/point-only contact is excluded; contact area and width relative to height influence ranking alongside support and strength preferences. The preview shows an illustrative bed beneath the prepared model. No bottom flattening, cutting, scaling, brim or raft geometry is added. If none of the evaluated positions provides flat contact within the build volume, custom placement is needed externally. This is a geometric placement heuristic, not an adhesion or warping simulation.

The approach follows [Prusa’s FDM design guidance](https://help.prusa3d.com/article/modeling-with-3d-printing-in-mind_164135) on orientation and bed-facing surfaces, and [Slant’s production guidance](https://www.slantpod.com/post/what-is-slant-3d-s-print-quality) on minimising support and testing actual prints. [Prusa’s warping guidance](https://help.prusa3d.com/article/warping_2011) also makes clear that bed adhesion depends on material, temperature and machine preparation. A larger base alone does not guarantee production reliability. Numerical coplanarity tolerance and ranking weights are app heuristics, not provider specifications.

## Optional edge improvements

**Design improvements** appears under **Improve for printing** only when it can edit the model, or on a copy that already has an edge edit (where it summarises that edit). The check uses triangle normals, not recovery of CAD features, and is limited to 100,000 triangles; it does not claim to identify every fillet or infer mating surfaces. Other shapes don’t show the card: edit their edges in the source CAD model.

For exactly recognised closed, outward-wound, 12-triangle solid rectangular parts, **Review Edge Improvement…** offers a 45° bottom chamfer or rounded vertical corners, adjustable in size with a before/after preview. These edits remove material and retain the overall envelope, not the original edge shape or contact area. The user identifies whether the affected edges are non-critical before saving. Detailed, hollow, already treated, open or ambiguous models are never replaced by their bounding box. Generated files are parsed and checked before saving as a separate local model; originals and cloud files remain untouched. Prepared load directions are remapped to the edited model’s axes, and new copies require a new upload and estimate.

The treatment choices follow [Prusa’s fillet/chamfer guidance](https://help.prusa3d.com/article/modeling-with-3d-printing-in-mind_164135) and [Autodesk’s additive design considerations](https://www.autodesk.com/learn/ondemand/curated/design-for-additive-manufacturing-with-fusion/5p0AhR0t0k8663u0OScBmt). External corner rounding is not presented as structural reinforcement; internal load-bearing fillets require the original CAD model and load context.

### Expanded placement and material matching

The placement search groups triangle normals by direction and evaluates the largest groups first, with a maximum of 30 candidates. Every candidate is checked against the whole mesh for actual bed contact and build volume. This is a bounded search, not a global orientation optimum; it does not search in-plane rotations or simulate support removal. Rotations preserve triangle geometry within floating-point precision. Existing six-position recipes remain readable. Oblique load directions are not rounded to an axis when creating an edge-edited copy; the user chooses a new direction when needed.

**Material suggestions for this use**, a small disclosure under the placement in **Optimise for purpose**, offers optional room-temperature rigidity (PLA) and toughness/occasional-flex (PETG) guidance. It uses exact catalogue profiles with confirmed availability and changes the material in Print configuration only when the user picks a suggestion. Unknown blends receive no inferred rating. Repeated flexing and warm environments require supplier performance data and application testing; the app does not invent fatigue or temperature ratings. The requirement is saved with the part and prepared recipe. Guidance follows [Prusa’s PLA guide](https://help.prusa3d.com/article/pla_2062) and [PETG guide](https://help.prusa3d.com/article/petg_2059); these describe material families, not Slant-specific performance certification.

### Reinforcement copies

**Reinforce this part** is a collapsed optional panel for closed, consistently oriented STL meshes up to 20,000 triangles. It supports internal ribs, triangular gussets, additive inside-junction fillets, mounting collars, overhang support chamfers, wall matching to line width, teardrop hole roofs, counterbore bridging layers, splitting with alignment pins, and three experimental treatments (internal shell gap, hole-wall ring gap, four-cell internal cavities). Operations use Euclid 0.10.0 (MIT, pinned in `Package.resolved`); the licence ships in the app bundle. Features are fused/subtracted as solids rather than exported as overlapping shells.

Choose a treatment, local dimensions, axis direction and a position measured from the model minimum. **Suggest Position** tries a bounded 27-position search for a geometric starting point. It is not a stress analysis or a complete search, and it does not infer the space needed by electronics or mating parts. **Update Preview** validates the candidate; the user reviews the placement before applying. Keep-clear boxes reject changes to protected regions, and a side-by-side cutaway shows internal changes without cutting the exported part. Suggestions may still need manual placement or CAD work, particularly for off-axis bores and complex joints.

Additive features must overlap existing material, make a measurable change, stay within the original overall envelope and avoid introducing a disconnected body. Mounting collars require a clear nominated bore and a complete annular seat at one end; they never drill an opening. The nominated clearance and protected regions need to include all required counterbores, fastener access and assembly clearance. Inside fillets add material, unlike the existing external-corner rounding tool. Another reinforcement can be added to the resulting copy, with each source version retained; on curved geometry, a repeatedly regenerated copy may instead report that a CAD edit is needed.

Before any solid operation, imported STL triangles are grouped into flat faces and each vertex is moved (by well under 0.1 µm) onto its face planes, with needle-shaped triangles merged into neighbouring polygons. Float STL rounding otherwise leaves faces slightly non-coplanar, which Euclid's Boolean operations turn into open seams around round holes. If a mesh cannot be cleaned this way, the original triangles are used and the exported-copy checks still apply. On export, a thin triangle that rounds to three collinear Float points is replaced by an edge flip with its neighbour rather than dropped, so the seam stays closed.

Print-process treatments depend on the layers, so they stay Z up (use **Turn about Z** to point them) and lock the saved copy's print orientation to Z up:

- **Overhang support chamfer** fills under a ledge with a 45° wedge so it prints without supports.
- **Match wall to line width** measures the wall through the region centre along local Y and thickens its +Y side to a whole number of extrusion lines. The line width (default 0.45 mm) is an estimate, because Slant does not publish its toolpath width.
- **Teardrop hole roof** adds a 45° point to an existing horizontal hole along local X. This enlarges the top of the hole, so avoid it where the top is fit-critical.
- **Counterbore bridging layers** cut a one-layer strip, then a one-layer square, into a downward-facing counterbore ceiling, so each layer bridges between solid edges. Set position Z at the ceiling and the layer height to match the print. This slightly reduces the screw-head bearing area.
- **Internal shell gap** and **hole-wall ring gap** (experimental) cut thin closed gaps inside the part, or around an existing vertical bore, so the slicer prints extra perimeters on both sides. A slicer may merge a gap that is too narrow for its toolpaths.

**Split with alignment pins** cuts the part on the region's local mid-height plane and drills matching blind pin holes in both halves. It saves two part copies, each of which can then be prepared in its own orientation. The joint is weaker than solid material, so keep it away from peak loads.

Teardrop, bridging, ring gap, wall matching and split are placed manually; **Suggest position** is not offered for them.

Internal cells remove material and create internal boundaries; they do not override Slant wall count or guarantee more strength. Their roofs slope at 45 degrees in local Z, so review the final print orientation. A solid surrounding envelope must provide the specified clearance from existing cavities and outer surfaces. Experimental copies require an explicit test-print acknowledgement. There is no automatic “approved” status or inferred strength percentage. All treatments require verification on representative prints before treating them as production-qualified.

Geometry checks cover closed directed edges, winding, envelope, connected-body count, serialized volume and protected-region changes. They do not prove absence of every self-intersection or guarantee finished tolerances, structural performance, adhesion or Slant’s toolpaths. Preview work runs off the main thread, has cooperative cancellation and a time limit, and invalidates on setting changes. Results are saved as separate local STL files with treatment/region metadata, preserving the source; a new upload and quote are required. The displayed geometric volume change is not a filament-use or price estimate. The 1.2 mm feature floor is an app heuristic, not a provider manufacturing specification.

### Auto-improve

**Auto-Improve & Save Copy**, in **Auto-improve** under **Improve for printing**, applies every treatment that the app can place reliably in one click and saves the result as a single new local copy. It uses the purpose set in **Optimise for purpose**; until a bracket, clip or custom part has a stress direction (and a custom part a description), the card’s summary says what to set first. There is no review step before saving, so check the saved copy's summary and preview before uploading it. **Return to Original** goes back to the untouched source.

It first chooses a print orientation for the part's purpose. Prepared copies and copies that are already locked to Z up keep their orientation. It then re-detects features on the current geometry and applies them in this order:

1. **Counterbore bridging layers** in downward-facing counterbore ceilings with two concentric round edges (0.2 mm layers).
2. **Overhang support chamfers** under downward-facing ledges up to 15 mm deep. Deeper ledges, and ledges without enough height below them, are reported for manual work.
3. **Wall matching** for inner walls 0.65–2.7 mm thick, which are thickened inward only to a whole number of 0.45 mm lines. Outer surfaces and the overall envelope are not changed.
4. **Inside-junction fillets** on up to 12 concave edges, longest first, sized from the thinner adjoining wall (1.2–3 mm). Decorative parts receive no fillets.

The copy keeps the orientation it was improved in, because these treatments depend on the layers. Every step goes through the same checks as a manual reinforcement, plus a volume-conservation check. If a step fails, it tries an alternative placement and is otherwise skipped, with the reason listed under **Skipped after checks**. The run stops after four minutes, and **Stop** discards the work without saving.

Teardrop roofs, mounting collars and edge chamfers or rounding change fit-critical or visible surfaces. They are therefore listed under **For your review** and never applied automatically. Ribs, gussets, splitting and the experimental treatments are also never automatic. Detection only recognises axis-aligned flat faces and round edges, so angled or freeform features are not treated. The 0.45 mm line width and 0.2 mm layer height are estimates, not Slant specifications. Test-print the copy before relying on it.
