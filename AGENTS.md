# Working on Slant Studio

Slant Studio is a native SwiftUI macOS 14+ app built with Swift Package Manager. Read README.md for user workflows and docs/API_REFERENCE.md for the Slant integration contract.

## How work is done

Every task follows this process. Scale the number of agents to the size of the task, but keep every stage. Use the strongest available model (currently Claude Opus 5.5) for every sub agent.

1. **Research and audit in parallel.** One agent studies comparable apps and platform conventions. Another audits the code for gaps, with file:line evidence, and checks each gap against the rules below. Every idea gets a frank verdict: genuinely useful, or polish.
2. **Shortlist.** Drop ideas that are already handled, low in value, or in conflict with "Behaviour to preserve", and record why each was dropped.
3. **Implement in parallel isolated checkouts,** one per non-overlapping file area, each branched from current `main`. Each implementer decides whether its feature is useful before building it, adds tests for new pure helpers, and checks its own work three times:
   - build and the full test suite;
   - its diff against "Behaviour to preserve";
   - an adversarial pass over edge cases.
4. **Merge into an integration branch, then review independently.** Three read-only reviewers each take one focus: correctness bugs; safety and privacy rules; and usefulness/UX, with a KEEP / CHANGE / REMOVE verdict per feature. Give reviewers the code, not the implementers' conclusions.
5. **Apply the findings.** Payment and lock changes get the closest scrutiny. Remove features judged not useful instead of keeping them.
6. **Verify:** full `swift test`, `./scripts/build-app.sh`, `codesign --verify --deep --strict`, and a check that the location permission strings are in the bundle's Info.plist.
7. **Ship.** Scan the outgoing diff for secrets and generated files, then fast-forward `main` and push. There is no CI, so local verification is the only gate.
8. **Report** what shipped, what was cut and why, what is unverified (especially native UI and live Slant responses), and any decision the owner should confirm.

## Build and verify

- Run `swift test` for the full suite. For model/order/location UI logic, use `swift test --filter 'ModelsUXTests|OrdersUXTests|ShellUXTests|DeliveryLocationTests|ModelLibraryActionsTests|UnknownOutcomeLockTests|OrderToolsTests|EstimateComparisonTests|MeshHealthTests|ModelFormatsTests|ModelThumbnailAndTrashTests|CloudFileDetailsTests|MarginTests|SavedProductsTests|OrderImportTests|BatchPayTests|DraftConfirmationTests|AddressPasteTests|ImportedSaleAmountsTests|OrdersImportFixesTests|OrderWatchRound5Tests'`. For the mesh and design tools, use `swift test --filter 'MeshRepairTests|MeshToolsViewHelperTests|MeshFitTests|MeshHealthTests|PrintReviewTests|ReplicaGeneratorTests|AccessoryDesignerTests|ScadSafetyTests|ImageTo3DTests|ImagePreparationTests|AnthropicJSONTests|AnthropicRequestTests|AnthropicStreamTests|AnthropicSupportTests|AnthropicClientStubTests|PersonalisationTests'` (the Anthropic and 3D client tests use stubbed transports and never reach the network).
- Run `./scripts/build-app.sh` to build and ad-hoc sign `dist/Slant Studio.app`. The script verifies the bundle signature and packages resources and the Euclid licence.
- Run SwiftPM builds and tests sequentially; do not edit source files during compilation.
- Report failing tests and unverified live flows explicitly. A successful targeted suite does not establish that the full suite passes.
- Don't trust the bundled OpenAPI alone for how Slant behaves. Live Slant has differed from it: `X-RateLimit-Reset` is epoch milliseconds, `DELETE` on a draft is refused, and `/orders/search` is routed as an order lookup. Check with read-only requests where you can, and record each finding in docs/API_REFERENCE.md.
- Verify native UI changes in the packaged app when computer access is available. `.build/`, `dist/` and `.swiftpm/` are generated and ignored.
- The full suite takes about 20 seconds. If it suddenly takes minutes, or a reinforcement test intermittently fails with "closed manifold", look for geometry output that depends on Set/Dictionary iteration order. Swift randomises hashing per process, and `SWIFT_DETERMINISTIC_HASHING=1` helps confirm the cause. Keep geometry iteration in index order.
- Do not create `StudioStore()` in tests: it reads the real Keychain key and model library. Put UI logic in pure functions and test those.

## Implementation map

- `StudioStore.swift`: shared state, API workflows, delivery details and persistence, including the session-only `importedSaleAmounts` (cleared with the loaded account data on Disconnect or a key change) and `LocalModel.sourceDetails`.
- `ModelsView.swift`: model library (one More menu that the context menu mirrors, destructive items last), the no-selection empty state, print configuration (one Material picker grouped by type), the persistent next-action bar (platform setup opens Create Platform or Settings via `platformSetupAction`), the Upload from URL sheet, the Source and licence panel and drag-out rows (On this Mac only; drops of drag copies or library files are ignored), and `ImproveForPrintingSection` — the STL-only tools in order: the Review for printing card (`PrintReviewCard`, always open; it only opens the review sheet), then collapsed Repair and simplify, Size and base (once the preview mesh has loaded), Optimise for purpose, Auto-improve, Reinforce (scrolled to and expanded by the review's `improveForPrintingOpenReinforce` notification), then Design improvements only when `edgeImprovementAvailable` or on an edge-edited copy; OBJ/3MF get only the Save STL Copy notice. The Import Model menu also opens Design an Accessory from a Photo… and Generate a Replica from an Image….
- `OrdersView.swift`: order composition (country first in the address; Paste Address… in Deliver to; the `UnconfirmedDraftNotice` with Look for Draft on Slant; the `studioDraftId` marker added to every Create; shipping provider, payment ID and reference fields under Advanced, opened when a duplicate copied a provider; Owner ID is edited only in Settings › Advanced), duplicate-as-new-draft prefill, the discard check, delivery country defaults and the country list, the toolbar Status menu (a status applies at once; Filters keeps dates and Newest/Oldest; its own section holds the local Needs attention toggle, which ends a banner Show's focus, as Show turns it off), the order detail (actions directly under the header; drafts have no Cancel, and their caption says why; tracking only for orders being made or shipped), the review sheet (up to four items listed, one fewer per extra receipt line — the Marketplace row and the imported-amounts estimate line, via `orderReviewItemListLayout` — and more scroll in a fixed-height box; never ViewThatFits or other measuring layouts, which hung the app under accessibility hit-testing; a definite refusal is explained in the sheet, quoting Slant for 400/422, rather than in a window alert; the estimate line shows only before a Pay is sent and never affects whether Pay is enabled), the Pay Several Drafts entry in the More menu, notification-click selection, the filtered-empty state (names the status/date filter, offers Show All Orders), and the receipt `LabeledContentStyle` for totals. The selected order resolves from all loaded orders, not the searched list, so a new draft or a just-paid order stays shown.
- `OrderTools.swift`: orders-list typed sort keys, CSV export (addresses opt-in, formula guard), detail facts and the marketplace reference from metadata (proper names for import's lower-case `source`; also shown in the orders table), the duplicate-draft guard state and notice (the newest 5 unconfirmed attempts, each with its marker and platform; `unconfirmedDraftCreatesOverflowed` keeps the guard once an attempt drops off, until a confirmed creation), copied item options summary, order item names (Slant returns `name: null` for Studio's drafts, so print items are named from linked library models or uploaded files; display only), advisory postcode checks, and small layout/copy helpers (search hint, tracking visibility, the review's large-quantity notice, composer heading and reused-address line).
- `Margin.swift`: the order-detail Profit check — strict money/percent input parsing, the order's Slant total, fee presets (assumed rates, all editable, shown as one labelled, dated summary line with Edit rates, latched open while it needs input), typed units sold for per-unit listing fees (not Slant item quantities) and Decimal estimated profit/margin maths. Imported sale amounts prefill only empty fields, once, with a caption naming the order. Only the preset and rates are saved.
- `ModelLibraryActions.swift`: model rename/export, cloud–local links, prepared-material mismatch, scale check and scaled copies, and menu helpers (Go shortcuts, modal-presentation guard; `isPresentingSheet` counts every store-driven sheet, including Size and base, Review for Printing, the replica and the accessory sheets).
- `OrderImport.swift`: Import Orders — bounded CSV reader (encodings, delimiters, Excel `sep=` line, RFC 4180), Etsy/Shopify/template detection, grouping rows into orders (repeated-row check only on rows carrying delivery details), per-order checks against saved products (units summed per product before resolving; shared once-per-order lines added once), the session-only Match products choices (explicit, never fuzzy, never saved), the session duplicate ledger, the paced, stop-on-unknown draft runner (it also stops when the key or platform changes; personalised uploads share its pacing), Show Drafts, and its sheet (Return never creates drafts). Fetch from Shopify results enter through the same `apply` as a chosen file (refused while a batch runs or the confirmation shows). Metadata is built by `orderImportMetadata` (`source`, `sourceOrderId`, the job's `studioDraftId`, and for Shopify `sourceItems` and fetched orders' `sourceShop`); sale-amount columns are read for the Profit check only and never sent; Look for Draft on Slant confirms unconfirmed ledger entries.

- `ProductCostCheck.swift`: Saved Products' Check Cost — ≤ 20 fresh estimates per check (one per print line, quantity × units typed; Compare estimates' spacing, reserve and 429 handling; never retried; stops after 3 failures in a row or when another task makes Studio busy; never sets `busy`), catalog prices for components and stationery (USD only), the delivery hint from `store.orders` using the Spending Report's rules, and its view. - `ImageTo3D.swift` / `MeshyClient.swift` / `TripoClient.swift`: image-to-3D providers — creates sent once, never retried, with unknown outcomes (408/409, 3xx, 5xx, transport, unreadable) kept apart from refusals; polling with backoff and capped `Retry-After`; resume points for Keep Waiting; the guarded download (https only, ≤ 128 MB, no credentials or cookies, every redirect checked, no IP literals or local hosts); `ImageTo3DConnection` with the session-only `unconfirmedRequests`; Keychain keys sent only to `imageTo3DKnownAPIHosts`; `SlantStudio-Generated3D-` temp folders. - `InternalWalls.swift`: internal walls — 0.25 mm slots open through the bed face, ≥ 2 mm from every other surface (proven by a nearest-surface index), regions ≥ 5 mm, 4 mm apart, spacing widened only past 6% of the volume; built directly without Euclid (bed face re-filled with a bounded, cancellable hole bridging), checked sound with the same shells, bounds and volume less the slots. Needs a flat bed face at Z min; never orients. Reinforce's Internal walls treatment and the print-ready copy use it.

## Behaviour to preserve

- Keep upload, estimate and order-draft actions accessible while scrolling. Explain missing prerequisites and mark estimates stale when their configuration changes.
- Preserve explicit delivery choices. Use the Mac region only as an initial country default; never silently substitute US when it is unknown.
- Request location only after the user's action. Keep manual address entry available, review suggestions before applying them, cancel pending work when the form closes, and ignore callbacks from cancelled attempts.
- Location suggestions must not silently overwrite a form. Applying one keeps name/email but clears the prior unit number. Do not store or log coordinates or add them to Slant requests.
- Location access requires the packaged app's permission descriptions. Do not remove those strings or trigger lookup on app/form launch.
- Slant traffic is production traffic. Preserve explicit charge/cancel review, unknown-outcome locks and credential redaction. Do not automatically retry mutations.
- The unknown-outcome lock is shared between the Orders review sheet, Pay Several Drafts and the Workbench, and records the action and the status it was sent from.
  - The lock, the unconfirmed draft-create notice and the import ledger last for the whole app session: a key change or Disconnect never clears them, because Studio can't tell whether a new key belongs to the same account. (Imported sale amounts are the opposite: they are account data and are cleared on Disconnect or a key change.)
  - Only these lift it: a confirmed success, a reload showing that recorded action's outcome, a definite HTTP 4xx refusal (not 408/409), or a failure before sending. Timeouts, transport errors and 5xx keep it. A 2xx to a pay whose returned order still shows DRAFT, or no readable status, is not a confirmed success: the lock stays until a reload shows the outcome.
  - This relies on both paths re-fetching the order before writing: pay requires DRAFT, and cancel requires an unchanged, cancellable status. Keep those checks.
- Slant refuses to cancel drafts and has no way to remove one, so `orderCanRequestCancellation` excludes DRAFT everywhere (Orders and the Workbench's guided check). Don't offer a draft Cancel again unless Slant's API changes.
- Background order checks are read-only. They never set `busy`, run while anything modal is shown, touch the unknown-outcome lock or `store.orders`, or save more than order IDs, statuses and times; the second (`updatedAt`) read obeys the same skip rules and stays off once Slant refuses it or returns it unsorted. Notifications carry no customer details, and their `userInfo` holds only the order ID. Only the seller's own actions (banner Show, a notification click) read orders by ID into `store.orders`, through `store.run`, and a click waits until nothing modal is shown and no request runs.
- Customer data stays in memory: personalisation (template values, Etsy and Shopify personalisation text), pasted addresses (dropped when Paste Address closes), Shopify orders' names, emails and addresses, and imported sale amounts. The seller's own address is the only address saved on disk, and only after the seller chooses to save it. Nothing derived from a buyer's personalisation goes into Slant metadata or file names.
- Draft creation (`POST /orders`) is never retried, automatically or from the alert's Try Again. After a create whose outcome is unknown (timeout, transport error, 5xx, 408/409, unreadable reply), every composer shows a notice naming each unconfirmed attempt's recipient and time (in memory only, kept for the whole session) and the next Create needs an explicit **Create Anyway**, with Don't Create as the default; only a confirmed creation clears it. Every draft carries `metadata.studioDraftId` (never at the expense of the seller's own fields); Look for Draft on Slant is read-only, and finding the marker confirms that attempt (an owner decision), but not finding it never clears anything. An attempt dropped from the 5-entry list keeps the guard through `unconfirmedDraftCreatesOverflowed`.
- Profit check uses the order's real Slant total in USD, Decimal money and editable, dated fee assumptions. Never save what the buyer paid or the units sold, or tie amounts to an order on disk. Amounts imported from Etsy or Shopify (USD only, never taxes) are kept in memory only, keyed by Slant order ID, until quit, Disconnect or a key change (an owner decision); they only prefill empty fields and are never sent to Slant. If items were left out of a draft, only shipping is kept. The pay reviews' estimated profit is advisory and never affects whether Pay is enabled.
- Import Orders creates drafts only, one request at a time after an explicit confirmation. It never pays, never retries, and stops the batch at the first unknown outcome (timeout, transport error, 5xx, 408/409, or a reply without an order ID); only a definite refusal lets it continue. Stopping or closing the sheet takes effect before the next request, never mid-request. Drafts are built only through `orderDraftPayload`. Imported names, emails and addresses stay in the sheet's memory: never on disk, in preferences, logs or Activity (counts only). Never invent an email, assume a country, pad a ZIP or match an item to a product without the user's choice; Match products choices stay in the sheet's memory too. Neither the Create button nor its confirmation may take Return. A change of key or platform stops the batch before the next request. Fetch from Shopify only fills the same sheet, through the same checks and confirmation.
- Pay Several Drafts pays only after one review of freshly re-fetched drafts (≤ 20, none pre-ticked) and an explicit confirmation whose default is Don't Pay; the Pay button is never the default and has no shortcut. It pays one order at a time while holding `busy`: re-fetch and `orderConfirmRecheck` (still DRAFT), record the lock, then the same `POST /orders/{id}`. It continues only when the order Slant returns has a placed status (not DRAFT, PAYMENT_ERROR or cancelled; unreadable is unclear and stops), and stops at any change, refusal, unknown outcome or failed re-fetch. It never retries, never starts or continues while any order's pay/cancel outcome is unknown, and requires the reviewed count, cent-rounded total, key and platform to be unchanged. Only the first draft for a marketplace order (source, order ID, store and items) is included, and none whose marketplace order already has a placed order. It warns while a draft create this session is unconfirmed. Stop and close take effect between orders only.
- Shopify talks only to the seller's `*.myshopify.com` host (no custom domains, no redirects); credentials live only in the `shopify-credentials` Keychain item, tokens and customer data only in memory, and only the shop address and the email choice are saved as preferences. Send Tracking fulfils only the units recorded in the draft's `sourceItems`, after a read-only check and a re-check before each write, one order at a time; `fulfillmentCreate` is never retried and the run stops at the first unknown outcome. Drafts from another store are refused, CSV-imported orders need a name-and-postcode match and are never auto-ticked, Email customers is off by default, and Return cancels the confirmation. Connect and Disconnect wait while a Shopify task runs or Send Tracking is open.
- Batch personalisation uses local OpenSCAD only (never `POST /files/openScad`, whose quota is 5 an hour), and only for products the seller explicitly chose a part for. It makes and checks every model of an order before uploading any, uploads with neutral names (the marketplace order number or "Personalised model", never the buyer's text), never retries, stops the batch at an unknown upload outcome with that draft unsent, never falls back to the plain model, doesn't add the models to the library and removes its temporary files.
- Dragging a model out offers only a temporary copy, never the library file, and drag copies are never imported back.
- No menu item or keyboard shortcut may upload, pay, cancel or send anything to Claude, Meshy or Tripo. Menu commands must do nothing while a sheet, alert or dialog is open in any window, including Settings. Files opened from Finder wait until nothing modal is shown and no request is running.
- Geometry tools stay STL-only. OBJ/3MF models are previewed and uploaded in their original format; the tools work on a separate STL copy.
- Geometry changes save separate copies and must retain existing validation; do not weaken checks to make tests pass.
- Claude is an advisor. It never edits triangles: Studio changes models only with its own validated tools, and only the plan steps the seller ticks (nothing is ticked by default). Never tell the seller a part is strong, approved, guaranteed or safe, or give a strength percentage. Studio's own measurements are always shown beside Claude's text, and “Studio's checks found no problems” appears only when every check passes, overhangs (under 2%) included. The model file and its name are never sent.
- No automatic resends. Claude messages and Meshy/Tripo creates, conversions and repairs are never retried. Every billed send is an explicit button that is never the default and has no shortcut, with the estimated cost shown first. The only automatic extra requests are the print review's one follow-up when no usable plan comes back and the accessory designer's one nudge when Claude answers without a tool call; keep each to one.
  - An unknown 3D create is remembered in `unconfirmedRequests` for the whole session, in memory only, and never cleared by a key or service change. Generating again asks first, with Don't Generate as the default.
  - Stop acts only at safe points and never cancels a credit-spending request mid-flight. Keep Waiting resumes the same task and never re-creates it.
- Conversation history is append-only, through `.assistant(message)`, and only when `canJoinHistory`. On a refusal, everything Claude wrote is discarded. Never run a tool call whose input has a problem; answer it with an error result.
- Photo consent is asked before the first send to each service (Anthropic, Meshy, Tripo3D), with Don't Send as the default. Every photo goes through `ImagePreparation` before it is sent.
- Design-tool data stays in memory: photos, briefs and measurements, conversations, plans and generated models until the seller saves one. Activity gets titles, counts, cost and status only. Nothing from these tools is sent to Slant.
- Each design-tool key lives only in its own Keychain item (`anthropic-api-key`, `meshy-api-key`, `tripo-api-key`) and goes only to its own API host, never to download hosts. Keys are redacted in every error and Activity line. API sessions don't follow redirects; downloads are https only, ≤ 128 MB, without credentials or cookies, with every redirect checked.
- Suggest Accessories sends one request per explicit press, never retried and with no follow-up, so it adds no automatic request. Its deny list and claim check run on every idea string, the identified object and the hint, whatever the prompt says: a refused object (a weapon, drug item or children's product, by its name, readable text or the hint) gives no new ideas but never removes ideas already held, a negation in cautions and how-to text ("PLA isn't food-safe") doesn't count, dropped ideas are counted and never shown, and claims (food-safe, strong, sells well and the like) are removed. Ideas live only in the sheet's memory. Use This Idea never sends, asks before replacing typed details (Keep Current Details is the default) and never drops a typed size.
- Never create closed internal voids: Slant bills each as a separate body (observed 25 Oct 2026). Reinforce, Size and base and Simplify refuse a copy with more shells than its input; Shell gap and Internal cells stay withdrawn, and the ring gap opens through the bed face. Lock-bearing records (`printPreparation`, `autoImprovement`, reinforcement Z-up) carry into every further copy.
- The print-ready copy is a separate local copy: it never changes the original's file, never selects itself, never uploads and never runs a step that moves fit surfaces (wall matching, fillets) without the seller's Add Fillets and Thicken Walls…. A step cut short by a time limit saves nothing, so its output never depends on machine speed. Text about internal walls names the price rise with its date and never claims strength.
- The fit-test render is local only, with `scadSafetyProblem`, the timeout and the memory cap, and never counts as one of Claude's renders or sends a request. Only a passing piece can be saved, and no fit-test or photo-comparison text may promise a fit; Studio's caption says it checks the piece's size, volume and reported fit sizes, not its shape.
- Claude-written OpenSCAD never runs without passing `scadSafetyProblem`, and runs only locally, with a timeout and `openSCADMemoryLimitBytes`. It is never sent to Slant's `POST /files/openScad`.
- Mesh tools are deterministic: the same bytes across runs and hash seeds, iterating in index order. Their results are separate STL copies, and no copy is saved if it fails a check its input passed (`meshToolMadeWorse`; Run Selected Steps also keeps the 220 mm fit).
- Replica Higher detail is for display pieces only, off by default and never remembered; Generate sends only the plan that was priced. A model too large to download or read (over 128 MB, over the replica limit, or a 3MF over 500,000 triangles or 128 MB unpacked) is a final stop: credits spent, no resume, and any earlier unconfirmed record for that generation is cleared. Only the replica pipeline may read meshes above the library's 500,000-triangle limit, and nothing above it is saved.
- Replicas are always scaled to the seller's typed size, because neither service knows the real size and their output units are unverified.

## UI conventions

- User-visible text uses British spelling (Optimise, Colour, Cancelled) and Title Case for buttons and menu items; section headings and disclosure labels stay sentence case. Never change Slant's API values (such as the `CANCELED` status) to match.
- Give each new DisclosureGroup outside a grouped Form `.studioDisclosureStyle()` so its whole label is clickable. Never apply that style to a window, List or Form: sidebar and list sections are disclosures too, and it breaks their rows and selection.
- Give a `TextField` with `.labelsHidden()` an explicit `.accessibilityLabel`: VoiceOver on macOS doesn't read a hidden label. Grouped-form footers use `.settingsFooterLayout()` so they stay leading-aligned, and sheets with long text set an `idealWidth` so a single line can't widen them.
- Use `ContentUnavailableView.search` only for a typed search. Say which status or date filter left a list empty, and offer a way back.
- Account setup (including design-tool keys and photo-sharing answers, in Settings › Design Tools) belongs in the Settings window, developer-only surfaces behind Settings › Advanced › Show developer tools, and seller tasks in the sidebar (Models, Orders, Catalog).
